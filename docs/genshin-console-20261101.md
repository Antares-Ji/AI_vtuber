## 供应商与主播

用户明确要求先使用已有 DeepSeek API，保留 OpenAI 手动切换，不自动回退。
控制台为 `http://127.0.0.1:3000/games.html?game=genshin`。
`POST /api/genshin/provider` 接受 `{ "provider": "deepseek" }` 或 `openai`；
当前任务或待回复队列未结束时拒绝切换。原神规划、单步决策与主播回复共用
此选择。DeepSeek 复用本地已保存的密钥；OpenAI 使用 `.env.openai.local`，
密钥不返回前端，两个供应商固定使用各自官方域名。失败不重试另一供应商。

DeepSeek 实际调用成功，`deepseek-chat` 请求对应服务返回 `deepseek-flash`，
回执保留实际模型名。OpenAI 先前实测为 HTTP429 / billing_not_active；

## BetterGI 真实通路

安装版本 0.66.0，核对源码提交 `0af68c28f6b0e714d5304625ce644736d508022e`。
配置目录读取46个顶层配置组、632条本机路线。SDK目录有129个签名，**目录不等于全部实测可用**。
此版 IPC v2 的 ping 是诊断，不能虚构为 task.* REST API。

路线和自动任务使用每次请求独有的 `AI-VTuber-Bridge-<UUID>` 官方 JS 配置组。
单独截图使用 BetterGI 自带的游戏截图热键（TakeScreenshot），避免脚本入口等待
主界面而无法观察。启动前临时配置 F9 和关闭截图不需要的实时自动触发器；
进程退出后只恢复本次修改的字段，保留其他配置变化。每次按键后必须收到
BetterGI 新写出的PNG文件才算取得截图，不将按键发送成功当作截图成功。

| API / Skill | 行为 |
| --- | --- |
| `/bridge/start` / `genshin:bridge-start` | 启动固定管理进程；确认权限不足后使用正常 Windows UAC |
| `/bridge/command` / `genshin:bridge-command` | capture截图、path已安装路线、task独立任务、window调整16:9 |
| `/bridge/observe` / `genshin:bridge-observe` | BetterGI截图→摘要校验→本地Qwen视觉API |
| `/run-goal` / `genshin:run-goal` | 本地观察→所选API决定一项任务→BetterGI执行；场景不确定则停止 |
| `/stop` | 取消模型请求、停止所拥有的BetterGI进程，等待原生输入释放回执 |
| `/installation`、`/catalog` | 脱敏配置、路线和源码接口目录 |
| `/obs/setup`、`/preview` | OBS原神场景和游戏窗口预览 |

独立任务接线包含：自动钓鱼、战斗、秘境、首领、伐木、七圣召唤、烹饪、进食、背包计数。
这些任务依赖用户自己的 BetterGI 队伍、策略与场景配置，尚未逐项实战验证。
路线执行使用 pathingScript.run；上游会捕获部分异常，因此 returned 不是到达目标证明。
`run-goal` 一次只执行一项任务，默认180秒，不会无限挂机；路线候选最多100条。

管理进程不接管外部已经运行的 BetterGI。每次命令结束都会关闭自己创建的实例，
因此空闲时 BetterGI IPC 离线并不表示桥接失效。持有原生输入互斥，取消/超时后
先停止所拥有的进程及其重启子实例，再通过项目原生 SendInput 释放键鼠。
清理未确认时保持占用而非报告空闲。父进程心跳丢失后管理进程停止任务。
第一次诊断发现 BetterGI 会自行提权重启；已据真实 AccessDenied 改为匹配权限的
管理进程，避免把原进程退出误当成整个任务结束。

截图保存于 `runtime/genshin/bridge/<session>/evidence-<id>/`，保留前后图、
脚本回执、尺寸和 SHA-256。控制台提供本机截图链接。图片经摘要验证后复制到
专用原神观察目录再交给本地17646视觉接口；原神未启用云端图像推理。
注意：BetterGI官方启动流程可能激活游戏和等待主界面，不是无副作用截图接口。
