# 鼠标交互连拍验收

## 2026-09-08 更新（以下新规则取代下文旧版参数）

- 点击“开始自动采集”联动开始交互记录，不能匹配共享目标则明确报错，不静默退回只拍停稳图。
- 支持鼠标左、右、中、X1、X2按钮及竖向／横向滚轮；键盘记录虚拟键码、扫描码、扩展位、按下／重复／抬起，组合键分别维护。仅目标游戏在前台时记录；不翻译为文本，切到其他应用取消当前手势。不要录入账号密码。系统保留键和未暴露的硬件键不能保证捕获。
- 按下／抬起／滚轮触发帧；按住期间目标30fps（实际需实测），每次18000帧／10分钟，保存队列120帧上限。E盘持久化，不无限堆内存；frames.jsonl逐帧记录，manifest每20帧及结束更新。旧的300帧、10fps、只记录左键规则已废止。
- 结束后自动启动流程候选分析，最多24个关键帧；滚动重叠才尝试拼接，不确定保留原图。可打开流程候选页改名和导出JSON。操作框只是位置候选，不是精确控件边界。
- 当前“设置→游戏／声音／提醒／按键”分类使用本次真实样本的标题栏与侧栏布局规则，不是通用模型；其他布局标未知。现有6张无输入记录，仅生成采样顺序边，不伪造点击因果。

独立于滚动拼接，入口位于 `/vision.html` 的自动采集面板内。

## 使用

1. 共享明日方舟窗口；选择主界面入口（例如设置）。
2. 点击“查找明日方舟窗口”，确认与共享画面相同，勾选确认后“开启交互连拍”。
3. 在游戏里短按一个按钮，停一秒；同一开关再次点击，停一秒；拖动音量滑块，抬起后停一秒；最后长按一个不会消耗资源的控件。
4. 点击“停止交互连拍”。展开每次操作的轨迹分类及画面链接，核对操作前、按住、释放、释放后帧。

## 通过标准

- 短按记录 down/up，持续时间为原生单调时钟差值；少于600ms、最大位移小于8物理像素归为短按。
- 长按达到600ms且最大位移小于8像素归为长按候选；有持续连拍。
- 最大位移达到8像素归为拖动候选，即使最终回到起点也不能归为短按。
- 移出窗口或失去前台焦点后中断当前操作，不保存其他窗口的鼠标坐标；抬起缺失不伪造完成。
- 操作前和释放后的图片可对照。两个相同位置的短按有 A→B→A 图像变化时可列“双态候选”，但不等于确认开关。
- 停止按钮先卸载观察器，再排空已排队的截图；停止共享也触发停止。页面失联10秒、游戏关闭、父服务退出或10分钟超时停止观察器。

## 限制与隐私

只读低级鼠标钩子，不注入操作、不监听键盘。钩子在系统层接收消息，但只向应用输出目标明日方舟窗口中的左键操作；窗口外坐标不保留。所有图片由用户明确共享的浏览器视频生成，未使用原生全屏截图。默认关闭，需显式开始。

目标连拍10fps，不保证实际速度。窗口共享请求最高30fps；浏览器后台限流、编码与磁盘速度可能降低实际采样。非常短的点击可能只有前后帧，不能保证按住期间拍到一张。原生事件时间与图像采样时间分别保存，不是硬同步。按住前的环形预览只保留内存中8帧；事件触发后才持久化相应帧。

每次上限300张截图、6000条事件、10分钟；队列满时主动停止，不无限积累。开始录制不会自动执行点击或拖动。机械手等鼠标外观不影响原生位置记录。

坐标基于 Windows 可见窗口边框，图像来自共享窗口；两者是否完全同框仍需首次人工确认，尤其 DPI、标题栏、窗口缩放。画面对比排除指针附近小块区域，但可能遗漏很小的控件变化；动画也可能误报变化。不宣称可靠识别开/关文字、控件完整状态数、音量0–100数值或范围。

保存目录为 `runtime/vision/interactions/<UUID>/`：`events.jsonl` 原生事件、`frame-*.jpg` 连拍、`manifest.json` 帧时间关联和分析。释放后连续点击会取消前一次延迟截图，避免错把下一次操作当作上一次结果。
