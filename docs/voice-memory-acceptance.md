# 语音、记忆与启动验收

本轮只处理四项：麦克风/回声/打断、输出与记忆一致、ASR 客户端、启动与重启。双机暂停，视觉作为下一主线。

## 一、真实麦克风与回声测试

打开 http://localhost:3000 ，选择麦克风，允许浏览器使用麦克风。先戴耳机验收，再换外放。下面数字是本轮建议的通过标准，不是已经实测的结果。

| 测试 | 怎么操作 | 通过标准 |
| --- | --- | --- |
| 麦克风输入 | 点击“开始说话”，读“今天测试语音，我准备开始学习”，结束并发送，重复 5 次 | 音量条随说话变化；5 次均能结束录音并得到转写；意思基本正确，不要求标点完全相同 |
| 耳机下打断 | 主播朗读时正常音量说“停一下，我换个问题”，重复 10 次 | 至少 9 次在持续开口约 0.5 秒内停止旧音频；全部 10 次都不得在停止后又恢复旧句；新问题能继续处理 |
| 外放回声 | 麦克风开启，用日常音量外放主播声音；自己保持安静 30 秒，重复 3 次 | 0 次因主播自己的声音误打断；0 次把主播的声音自动作为新问题发送 |
| 外放下打断 | 保持相同设备位置和音量，重复上面的打断 10 次 | 同耳机标准；若失败，记录外放音量、麦克风设备和距离 |
| 停止/重新开始 | 录音或生成途中停止，再重新开始，连续 5 次 | 没有旧字幕/旧语音回流；按钮不会永久卡在“识别中”；每次能重新录音 |

500ms 从人持续开口算起，不从服务器请求取消算起。当前 VAD 持续语音确认约 280ms，是代码门槛，不代表实际停声延迟。可用手机录屏带声音回放估算；无法测量时写“未测”，不要写通过。后台 http://localhost:3000/latency.html 中的取消耗时也不能直接替代可听停声时间。

## 二、长期记忆保存在哪里

主数据是 `E:\Github\AI_vtuber\data\memory.db`（SQLite）。会话、长期记忆、证据、候选和审计均在其中；不是保存到大模型权重中。

- 普通聊天在回复完成后写入会话记录，不自动等于长期事实；最近上下文只取有限轮数，会话表也有保留上限。
- 普通聊天提炼出的候选，在导演工作台点“确认选中记忆”后才成为长期记忆。
- 明确以“请记住：…”等形式开头的保存指令，是另一条直接保存路径（仍有内容过滤）。测试该路径时不要勾选训练提示开关；代码中 training=true 会将输入留给候选审核路径。
- `data\training-memories.json` 只导出有效的 training 类型记忆，不是整个数据库的备份。
- `runtime\brain-state.json` 是情绪/认知等运行状态，不是长期记忆主库。旧 `data\memories.json` 主要用于历史迁移。

### 手动持久化验收

1. 用固定昵称“记忆验收用户”，发送“请记住：我的项目测试代号是青柠灯塔。”，等待完整回复。
2. 打开 http://localhost:3000/studio.html 的“记忆训练”，搜索“青柠灯塔”，确认有效记录确实存在。只听到主播说“记住了”不算通过。
3. 在项目目录运行 `npm run restart:server`，看到 PID/instance 核验成功。刷新页面，保持同一昵称。
4. 问“我的项目测试代号是什么？”：应回答青柠灯塔；工作台记录仍应存在。换新昵称不应把原用户的记忆当作新用户的事实。
5. 验证候选路径：普通聊天说一个明确目标，点击“结束并自动提炼本场”，审核候选后点“确认选中记忆”，再重复重启检查。
6. 测试结束可在工作台对专用测试昵称执行“忘记用户”，不要对日常昵称操作。

数据库使用 WAL。运行时 `memory.db-wal` 可能包含最新写入，不能只复制主库就认定备份完整；备份请停服务后复制，或使用 SQLite 一致性备份。

## 三、ASR 与异常处理

ASR = Automatic Speech Recognition，即自动语音识别：把麦克风声音变成文字。TTS 是相反方向，把文字变成声音。当前 SenseVoice 路径仍是批量识别；原生流式路径则持续送 PCM 小片段，用同一识别缓存逐步返回文字。

已有代码/测试覆盖：迟到文本/PCM 不恢复旧会话；前端录音连接失败回退批量；服务端断连取消上游请求；ffmpeg 退出后再清理临时文件。原生客户端进一步处理连接/结束超时、取消后迟到消息及音频资源释放，真实模型体验仍待验证。

本轮新增并实际通过的客户端测试：等待 final 超时回退、socket close 释放音频上下文、取消后迟到消息丢弃、等待音频设备 resume 期间取消不再重建音频图、发送队列积压时显式失败并回退批量、44.1kHz 连续 4096 帧分片重采样与一次性处理逐样本相等。超时计时器正常清理。

缺少 Paraformer 流式权重时，原生功能保持关闭，不影响现有批量识别；不能把“接口已写好”当作“原生模型已验收”。

## 四、启动与重启修复

旧问题：端口查询使用 SilentlyContinue，权限失败被当成端口无人监听；启动副本失败后，只检查 HTTP 200，可能误用旧实例的健康响应报告成功。

现在：端口查询失败直接报错；核对主进程的完整项目路径才停止；等待旧监听释放；为新进程生成唯一实例 ID；健康接口必须同时返回预期实例 ID 和新 PID 才成功。新进程提前退出会立即报错。

2026-09-06 本轮真实验证成功：PID 16884，实例 ID `6d9184c1-5142-49f5-9c58-a3586af44dd6`。这是当时实例，后续正常重启会变化。此前旧实例上的延迟测量不作为新版验收证据。

Windows CMD 命令：

```bat
cd /d E:\Github\AI_vtuber
npm run restart:server
npm run services:status
npm run test:realtime
node tests/server-brain-policy.js
```

若端口查询权限不足，命令现在明确失败；需要在有相应权限的终端运行，不能再悄悄当作服务离线。
