## 0. 前提与边界

在开始之前先把范围钉死,避免设计跑偏。

| 项 | 说明 |
|---|---|
| **本项目只做** | 产出台词与思考过程(文字层) |
| **不做** | TTS、口型同步、发音评测——由组内其他成员实现 |
| **算力约束** | 已解除。有双 RTX 6000 支持,**设计按"效果优先",不按"省钱优先"** |
| **人为介入** | 常态存在,不是异常。设计必须为人留接口(见 G 段) |
| **主场景** | 游戏直播(明日方舟) |
| **近期交付** | 10–15 分钟、有人类导演监督、可复盘的一段直播 |

### 0.1 已确立的方向性结论

这几条是讨论后定下来的,后续设计不要推翻:

1. **"助手人格"和"表演者人格"是两回事。** 大模型出厂都是助手:乐于帮忙、有求必应、礼貌。这套默认人格搬到直播上必然无聊。原因有四条:训练奖励、提示词预设、问答式结构、以及**她没有自己的目标**。
2. **一句话目标:稳定的性格 + 不可预测的反应。**
   而"一味听观众的"两头不占——既没性格,也不可预测(观众自己都猜得到她会照做)。所以无聊是结构性的,不是调提示词能救的。
3. **记忆当数据库,不要当文章反复缩写。** (桌宠项目已验证:反复总结会导致"人格坍缩"——像传话游戏,几轮后只剩形容词。)
4. **梗不是设计出来的,是筛出来的。** 真实主播的梗走的是"事故 → 观众有反应 → 她自己发现有效 → 主动复用 → 变异 → 用烂了退役"。要建的是**循环**,不是梗库。
5. **梗靠剪辑出圈,不只靠直播。** "哪个片段值得剪"和"哪个瞬间值得变梗"是同一个判断,可共用一套打分。
6. **模型不是查数据库,是按概率续写;默认人格是服务员。**
   它被 RLHF 训成"有帮助 + 无害 + 礼貌",又被奖励"让用户满意",所以**顺从是概率上最省力的路**。
   → **人格化不是"教它做人",是"持续对抗它的出厂设置"。** 详见 T 段。

- `【已有】` 需求书里已出现的字段或要求
- `【可借】` 桌宠人格成长系统可参考的设计
- `【新】` 必须从零设计

## A. 人设本体(静态,写死的部分)

- **A1 身份卡** `【新】`
  名字、年龄感、性别、自称(我/本小姐/咱)、对观众的称呼(各位/家人们/你们这些家伙)。
- **A2 背景故事** `【可借】`
  从哪来、为什么开播、有什么"经历"。
  **要求:设定经历与真实经历分开存储**——她"记得"的事 ≠ 设定里的事。
- **A3 性格** `【新】`
  **不许只写形容词。** 必须拆成四样:
  - **矛盾点**:两副脸分别是什么、**什么条件切哪副**(这是"人格飘"的唯一解药)
  - **边界**:什么会让她生气 / 沉默 / 拒绝 / 破防
  - **缺陷**:会记错、会固执、会嘴硬、会被带偏——**像人靠缺陷,不靠优点**
  - **说话习惯**:口头语、惯用句式、句子长度、句尾语气、语速倾向
- **A4 立场表** `【新】`
  永远支持什么、永远讨厌什么(游戏内、玩法上、观众行为上)。这是执念与梗的来源。
- **A5 能力自评** `【新】`
  她**以为自己**强在哪、弱在哪。**允许与实际不符**——自我认知偏差是最好的笑点来源。
- **A6 目标栈** `【新】`
  - 长期:这个游戏我要打到哪 / 我要成为什么样的主播 / 有个执念想完成
  - 中期:这一局我想赢 / 有个战术很想试一次
  - 短期:这一波我想秀 / 我想把刚才的场子找回来
  用处:每句话都能回答"这符合我哪个目标"。**有目标才有关注点,有关注点才有主动话题。**
- **A7 关系网** `【可借】`
  对观众、对队友、对其他 AI/角色、对"创造者"分别什么态度。
- **A8 情绪谱** `【新】`
  有哪几种情绪、每种怎么表现、分几档强度、与 A3 的两副脸如何对应。
- **A9 禁区(反向清单)** `【新】`
  明确写她**不说什么**。至少覆盖:
  - 无脑夸、三连排比、"作为一个 AI"、总结式收尾
  - **网络梗默认禁用** + 唯一例外(允许她嘲讽观众刷梗)
  - 政治/色情/他人隐私等硬红线
  > 这是全表**最省事、效果最大**的一条。

## B. 人格运行机制(动态)

- **B1 目标栈的维持与更新** `【新】`
  谁改、什么时候改、改动要不要人工批准。
- **B2 情绪状态机** `【新】`
  情绪要有**惯性**、有**半衰期**、被**具体事件**点着。**不能只是一个 `mood` 字段。**
- **B3 精力 / 状态量** `【新】` ⚠️ 移出近期范围
  随直播时长下降 → 播到第三小时开始敷衍、反应变慢、话变短。
  **这个机制极像人**,真实主播就是这样。
  > **修订**:15 分钟的交付物里,这条**既看不出效果、也无法验证**。移到远期。近期如果要保留,只留一个弱化版(开场有精神、结尾略疲)。
- **B4 冲突仲裁规则** `【新】`
  三个信息源——她自己的判断 / 弹幕建议 / 局面事实——冲突时谁说了算,由性格决定。
- **B5 采纳率参数** `【新】` ⚠️ 已修订
  弹幕被采纳的比例。**这个数字比十句形容词都管用。**
  > **修订**:"真实主播约两三成"**是我编的,没有任何数据来源**。标注为**未标定假说**——第一批录像里人工数一遍,用实测值替换。
  仍待补:**"傲娇调低、温和调高"只是方向,不是机制**。必须补上"采纳率的具体数值从 A3 的哪个字段来",否则又是一个形容词。
- **B6 拒绝 / 反驳机制** `【新】`
  拒绝要**说得出理由**,且允许"嘴硬然后偷偷照做"。
  例:"你们别闹,这波听了就寄了。""行行行听你们的,输了你们负责啊。"
  **这是"傲娇"的可执行定义**——否则"傲娇"永远只是个形容词。
- **B7 人格一致性校验** `【新】`
  怎么**自动发现**她飘了(如连续偏离 A3 的边界)。
- **B8 人格演化** `【可借】` ⚠️ 移出近期范围
  允不允许她变、多久评估一次、谁批准生效。参考桌宠:成长总结必须人工审核才生效,且放在离线批量做,不进对话主链路。
  > **修订**:同上,15 分钟交付里无法验证,移到远期。

## C. 感知输入(她能"看到"什么)

- **C1 游戏状态** `【已有】`
  关卡 / 费用 / 部署栏 / 可部署格 / 干员 / 朝向 / 技能 / 部署确认 / 胜负。
- **C2 自己的战况** `【新】`
  刚才那波操作对不对、有没有失误。**她得知道自己菜在哪。**
- **C3 弹幕** `【新】` ← **造梗的命门**
  内容、频率、**复读**、**指向**(在重复她哪个词)、时间戳。
- **C4 观众数据** `【新】`
  同时在线、人数变化、礼物、关注。先确认链路能拿到哪些。
- **C5 时间感** `【新】`
  直播时长、距上次互动多久、距上次说某句话多久。
- **C6 短期对话记忆** `【新】`
  刚才自己说过什么(防止复读自己)。
- **C7 人为介入信号** `【新】`
  见 G 段。

## D. 表达输出(她"怎么说")

- **D1 说什么** `【新】` 内容选择:评论操作?回应弹幕?自言自语?
- **D2 怎么说** `【新】` 语气、长度、句式、口头语密度。
- **D3 什么时候说** `【新】` 时机选取。
- **D4 什么时候不说** `【新】` **与 D3 同等重要。** 沉默是人的特征,不是故障。
- **D5 弹幕分类处理** `【新】`
  提问 / 赞美 / 挑衅 / 玩梗 / 无关 / 恶意——六类走六条不同的路。
- **D6 主动说话的四类动机** `【新】`
  | 动机 | 触发 | 例 |
  |---|---|---|
  | 局面需要 | 危险 / 机会 | "等等等等,这波不对。" |
  | 想秀 / 立人设 | 场面允许 | "看好了,这个操作我练过。" |
  | 被激到 | 弹幕挑衅 | "你说我不行?那我偏要。" |
  | 憋不住 | 长时间沉默 + 情绪积压 | 自言自语碎碎念 |
  > 这段是"AI 自己思考话语让直播更有趣"的落点。**它的燃料是 A6 目标栈**——没有目标,主动说话只能靠计时器,又变成播报器。
- **D7 "值不值得说"打分 + 冷却** `【新】`
  不是到点就说。人沉默是有原因的;到点开口的是播报器。
- **D8 表达形态分级** `【新】`
  长表态 / 短反应 / 一个词 / 一声叹气。
- **D9 节目效果类型** `【新】`
  自嘲、炫耀、破防、装死、甩锅、找补。
- **D10 事故处理** `【新】`
  被问住、答错、被识破、被恶意针对——分别怎么接。

## E. 记忆层

- **E1 分层结构** `【可借】`
  - **核心档案**:人设 + 关键事实(偏好、重要事件)。每轮必带,人工可编辑
  - **事件日志**:所有对话原文 + 时间戳 + 重要度。**只追加,永不删改**
  - **检索层**:按相关性取 top N。**不全量读取**
- **E2 观众侧记忆** `【新】` ← **直播特有,重点**
  记不记具体某个观众?记昵称、发言风格、老观众自己的梗?
  **"她记得老观众"这件事威力极大**,是"陪伴感"的直接来源。
- **E3 立场记忆 vs 传闻记忆** `【新】`
  她**知道弹幕这么说** ≠ 她**认这个说法**。
  否则观众刷十遍"你菜",她就真成菜的了。
- **E4 检索机制** `【可借】`
  桌宠用的是本地 bigram 打分(为省钱)。**本项目 token 不设限,可以上向量检索。**
- **E5 写入机制** `【可借】`
  搭对话顺风车:回复时顺带吐结构化字段,只多几十个输出 token。
  参考形状:
  ```json
  {
    "reply": "给观众看的回复",
    "facts": [{"text": "用户在做桌宠项目", "importance": 3}],
    "mood": "开心"
  }
  ```
  注意:**`importance` 不要完全交给模型自评**——模型会给所有东西打高分,导致核心档案被水话占满。
- **E6 遗忘 / 淘汰** `【可借】`
  核心档案塞满时,把最低重要度的**移回事件日志(不删除,仍可检索)**。
- **E7 关系值 / 亲密度** `【可借】`
  对整体观众的关系值,分档影响语气(参考桌宠:0-30 礼貌 · 30-70 自然 · 70-100 亲昵)。
  桌宠还有衰减机制(3 天没互动每天 -1),直播场景需不需要,待定。

## F. 风格与梗层

### F1 四层风格(由便宜到贵,按顺序做)

| 层 | 是什么 | 例子 | 成本 |
|---|---|---|---|
| **用词习惯** | 口头语、称呼、句尾语气 | 总叫观众"各位"、句尾带"吧" | 低,**效果最快** |
| **关注点** | 她永远先看什么 | 只盯伤害数字 / 老关心队友死活 | 低 |
| **立场执念** | 永远支持 / 永远讨厌什么 | 誓死不用某角色 | 中 |
| **梗** | 具体一句话、一个事件 | 见 F2–F7 | 高,要循环 |

> **先做前两层垫底,再上梗。** 不然梗会飘在没有风格的空气里。

### F2 梗库结构 `【新】`

```json
{
  "id": "m-007",
  "type": "口误 | 事故 | 口头禅 | 绰号 | 执念",
  "surface": "她当时的原话",
  "context": "当时局面是什么",
  "origin": "events.jsonl 第 N 行",
  "reaction": { "复读词": "草", "密度倍数": 3.1 },
  "use_count": 7,
  "last_used": "时间戳",
  "cooldown_until": "时间戳",
  "status": "active | cold | retired"
}
```

`status` 与冷却必须有。**一个梗用太多次会死**,她自己也该觉得"这个玩烂了"——这个行为本身就是人味。

### F3 反馈信号采集 `【新】` ← **命门**

判断"刚才好不好笑"的唯一客观信号是弹幕:
- **密度突变**(沉默 5 秒突然刷屏)
- **复读**(同一个词连刷)
- **指向**(弹幕在重复她刚说的某个词)

这是免费的标注数据,比任何人工评分都准。
**拿不到带时间戳的弹幕,整个循环不成立。**

### F4 发现 → 固化 → 复用 → 淘汰 循环 `【新】`

**架构上最关键的分工:离线学梗,实时用梗。**

```
实时(直播中):只检索 + 复用已有素材。轻、快
离线(复盘时):看录像 + 弹幕 → 发现新梗 → 写进梗库 / 淘汰旧梗
```

实时发现梗太贵、她也没空(正在打游戏)。
这个分工正好卡在需求书的"10–15 分钟、人类导演监督、**可复盘**"上。

- **"不经意"复现** = 情境相似触发旧梗(检索驱动)
- **"有意"造梗** = 执念槽 + 主动往那靠(目标驱动)
  两种机制,同一个数据库。

### F5 执念槽 `【新】`
一次只带 **1–2 个**执念。槽位满了,新执念进不来。
**梗的威力来自稀缺。** 满嘴都是梗 = 油腻,比没梗更难看。

### F6 梗密度上限 + 自动淘汰 `【新】`
每 N 句最多 1 次。观众反应下降 → 自动冷却 → 退役。**她得会放手。**

### F7 高光切片判断 `【新】`
哪个瞬间值得剪 = 哪个瞬间值得变梗,共用一套打分。

### F8 三道刹车(硬约束)
1. **禁网络梗写进硬规则**——不写她一定滑回去。留一个口子:允许她**嘲讽观众刷梗**("你们除了刷这个还会干嘛?"),这个口子反而最有人味。
2. **梗密度上限**(见 F6)。
3. **淘汰机制**(见 F6)。

## G. 人为介入

> **这段最容易做坏——做坏了,她就变成导演的提线木偶,人格白设计。**

- **G1 介入分级** `【新】`(必须分级,不能只有"介入/不介入")
  | 级别 | 名称 | 含义 |
  |---|---|---|
  | L0 | 全自主 | 她自己决定说什么 |
  | L1 | **软推** | 人给方向("聊聊刚才那波"),她自己组织话 |
  | L2 | **硬给** | 人指定一句话 |
  | L3 | **接管** | 人直接替她输出 |
  | L4 | **刹车** | 静音 / 切画面 / 立刻终止 |
- **G2 各级频率上限** `【新】`
  建议 L0 占大头、L1 为主、L2 少量、L3 极少。
  **L3 太多 = 人格失效。**
- **G3 时机窗口** `【新】`
  哪些时段**禁止打断**(操作中、关键局、一句话说到中途),哪些可以。
- **G4 导演实时面板要显示什么** `【新】`
  她当前目标 / 情绪 / 精力 / **她即将要说的话(预览)** / 弹幕热点 / 上次介入是什么时候。
  **没有"即将要说的话"的预览,人根本来不及介入。**
- **G5 介入怎么进记忆而不污染人格** `【新】`
  她事后"记得"这句是自己说的,还是记得是导演喂的?
  **两者取舍必须先定:**
  - 记成自己的 → 人味儿好,但一致性差
  - 记成外来的 → 一致性好,但会显得机械
- **G6 日志字段** `【已有】`
  `human_override` 要记:介入级别、介入内容、**她原本打算说什么**。需求书已有该字段,需扩写。
- **G7 冲突处理** `【新】`
  导演指令 vs 她的目标冲突时谁赢?
  建议:**由性格决定配合度**,允许她嘴上不情愿、边抱怨边照做——这反而好看。
- **G8 紧急刹车** `【新】`
  触发条件(说错话 / 事故 / 敏感词)、从判断到切断的时间预算、切断后怎么**回场**(不能直接卡住)。
- **G9 自主度指标** `【新】`
  把介入率做成可测数字(如目标 < 20%)。
  **这是她"是不是独立人格"的量化答案。**
- **G10 复盘介入** `【新】`
  人标注高光 / 翻车 / 新梗候选 → 怎么回写进记忆和梗库。
  **这是最快的人机协作方式**——真实主播也有剪辑师和经纪人干这事。

## L. 时序与延迟架构

> 核心判断:**不是一条串行链,是三条时间尺度完全不同的回路。** 串行跑必然互相拖。

### L1 三条回路(必须并行)

| 回路 | 时间尺度 | 能不能慢 | 跑在哪 |
|---|---|---|---|
| **游戏操作** | 毫秒~秒 | **不能**。费用回好就得下人,慢一拍就崩 | ⚠️ 见下方修订 |
| **即时解说** | < 1 秒 | 要快,慢了出戏 | 快通道 |
| **深度对话** | 几秒~十几秒 | **可以慢**。正经问题本来就该想一下 | 慢通道 |

真人主播就是这么跑的:手在玩,嘴里碎碎念,脑子还在想一个正经问题。

> **⚠️ 修订(2026-09-28 评审后):**
> "游戏操作"这行的**执行主体尚未确定**:需求书对训练阶段明确写了"不要自动执行游戏操作",而本表把它画成 AI 全自动回路,两者冲突。
> 近期交付的 10–15 分钟直播里,部署/技能/撤退到底是 **AI 自动执行 / 人类确认后执行 / 人类完全代操作**,必须先定。三种答案会让 L 段结构完全不同。
> **在定下来之前,"硬实时游戏脑独占一卡"这个前提不成立**,下面的 L7 与 L9 都要打折看。

### L2 快慢双通道 `【新】`

| 通道 | 谁来干 | 干什么 | 延迟 |
|---|---|---|---|
| 快 | 规则 + 模板 + 小模型 | 局面反应、短感叹、口头禅、垫场词 | < 300ms |
| 慢 | 大模型 | 回答弹幕、长评论、复盘 | 几秒,允许 |

### L3 把延迟变成表演素材 `【新】` ← 价值最高的一条

延迟不是必须藏起来的缺陷。真人也会说:

> "等一下,我先打这波。" / "你刚说啥?打完这波回你。" / "嗯……让我想想。"

**用一句垫场话把等待变成节目。** 观众看到的不是"卡了",是"这人在忙"。
配一个垫场词库,按性格选。

### L4 弹幕攒批,不逐条回 `【新】`

不要一条弹幕调一次。攒 **1.5–3 秒**成一批,一次调用处理多条,挑 1–2 条回。
既省调用,又更像人 ——**真人也不是逐条回,是挑着回。**

### L5 预生成 + 缓存 `【新】`

弹幕高频问题类型可预测(问角色、问配置、问为什么这么打)。
离线或用便宜模型提前批量造一批候选回答,命中直接取,**延迟接近 0**。

### L6 发言调度器:"想好了" ≠ "现在说" `【新】` ← 核心机制

- 大模型算完了 → **进队列,不阻塞任何东西**
- 等合适时机(**游戏不紧张 + 上一句说完了 + 现实脑放行**)再吐出来
- 时机不对就**压着**;压过头就**丢掉**

**人也会憋着等时机。这个机制本身就是人味。**

### L7 资源隔离 `【新】` ⚠️ 已修订

> **原表述"游戏 AI 独占一张 RTX 6000 + 语言层用另一张"作废。**
> 原因:双 RTX 6000 在**北理工导师处**,型号/显存/系统/网络/SSH **全部未确认**,且其预定用途是**批量训练与评测**,**不是实时推理机**。而实时回路要求毫秒~秒级,走远程网络本身就否决了硬实时。
> **实时直播大概率跑在本地 5070(8G)/5080 上,那里没有双卡。**

修订后的写法:

- **先确认实时直播跑在哪台机器。** 这是 L 段一切前提中的前提
- 若在本地单卡:**双卡分工不成立**,只能用"单卡内优先级 + 降级"(游戏识别优先,语言层排队或降级到小模型)
- 若直播确实跑在双卡机:**再谈分工**。且要确认那台机的网络往返能否满足实时
- **训练用双卡、直播用本机,是两件事,不要混为一谈**

**原句"优先级竞争问题直接消失"是错的** —— 它只在前述条件成立时才成立。

### L8 减负两条 `【已有】`

- 固定 UI(费用、卡片)走 **OCR + 状态机**,不调 VLM(需求书里的快路径)
- **状态差分**:画面没变就复用上次识别结果,不逐帧重认

### L9 延迟预算与实测目标 ⚠️ 已修订

> **原表述"弹幕时间 → 她开口时间,p50 < 2 秒,p95 < 5 秒"有三个错误:**
> 1. **算术不成立**:L4 要求攒批 1.5–3 秒,L1 又允许深度对话"几秒~十几秒",加起来 p50 必然超 2 秒
> 2. **量了别人的东西**:"开口时间"要等 TTS 合成完并开始播报,而 TTS 不在本模块范围内(L7 还把它划在语言层卡上),本模块无权保证也无法单独归因
> 3. 没区分快慢通道,一个数字管不了两类发言

修订后的写法:

**按通道分别定预算,终点定在"文本产出"**

| 通道 | 起点 | 终点 | 目标 |
|---|---|---|---|
| 快通道 | 局面变化 / 弹幕到达 | 文本产出 | p50 < 500ms |
| 慢通道 | 弹幕进批 | 文本产出 | p50 < 3s,p95 < 8s |
| 端到端 | 弹幕到达 | **声音真正开始播报** | **跨模块联合指标,和语音负责人共同认领** |

补充规则:
- **攒批窗口(1.5–3s)是慢通道延迟的下限**,不能和 p50 目标分开谈
- 超预算的必须走垫场话,或直接丢掉(垫场话本身要算进预算)
- 需求书已要求测每步 p50/p95,纳入同一套测量
- **本模块的 KPI 是"文本产出延迟";端到端只做联合观察,不作为本模块的承诺**

### L10 更根本的重构

**她的"思考"不该发生在收到弹幕之后。**

应该是:一直有一条**持续的内心活动流**(基于局面 + 目标 + 状态),弹幕只是**插进来的打断**。

这样她随时有话说,不用从零开始想。延迟问题从源头小一大截 —— 而且这正是"AI 自己思考话语让直播更有趣"的落点。

## M. 不最优机制(自限 / 失误 / 表演性风险)

> **底层原则:有趣 ≠ 不最优,而是「有目的的不最优」。**
> 观众喜欢的不是"打得菜",是"**她有自己的打法,并且为此付出代价**"。
>
> 一切"不最优"**必须能追溯到目标或性格**。追溯不到的,观众会归因成"AI 坏了",不是"这人有意思"。

### M1 自限(主动、有意、稳定) `【新】`

本质:**她给自己加约束,而这个约束是她目标栈的一部分。**
实现上就是 A6 目标栈 + A4 立场表的延伸,塞进 F5 执念槽。

例:只用某职业干员 / 不用六星 / 只带三个人 / 肉鸽必选某收藏品 / 这次走某条非最优路线。

**四条硬要求:**

| 要求 | 为什么 |
|---|---|
| **必须说出口** | "我这次不用 XX,我就不信我打不过。" 不说出来,观众只看到"她打得烂",看不到"她在挑战" |
| **要有期限** | 这一局 / 这一周,到期换。不然会腻 |
| **要有强度参数** | 强度越高越容易翻车,翻车就是节目效果 |
| **要能追溯** | 每个决策都能回答"这是因为我立了那条规矩" |

### M2 真失误(能力不足,无意的) `【新】`

**这个不用设计,它天然存在。** 现在视觉和决策本来就不够强,失误一定有。
要设计的是**失误的处理**:

1. 她得**知道自己失误了**(对应 C2 自己的战况)
2. 反应方式由性格决定:嘴硬 / 甩锅 / 自嘲 / 沉默 / 找补
3. 失败后**更新短期计划,但不改人物设定**(桌宠那边已想过,机制可借)

**真失误必须如实记录,不能美化。** 需求书强调"不能把三星等同于所有动作成功"——这些失败是训练数据,是资产。

### M3 表演性风险(有意的,最危险的一条) `【新】`

故意送人头、故意输 ——**观众看得出来,而且会反感,因为假。**
真实主播的"故意出错"其实是这四种,**没有一种是"随机注入错误"**:

| 类型 | 是什么 | 例 |
|---|---|---|
| **作死但能兜住** | 明知危险还要秀,有实力兜底 | 高光的主要来源 |
| **玩梗式翻车** | 重复某个经典翻车操作,观众等的就是那个翻车 | 观众在期待 |
| **嘴硬导致的翻车** | 坚持不听劝 → 翻车 → 继续嘴硬 | **性格一致性的副产品,不是"故意出错"** |
| **教学式失误** | 故意做错来解释为什么错 | 游戏区主播很自然 |

### M4 实现方式:风险偏好参数,不是随机丢操作 `【新】` ⚠️ 已修订

> **原表述"成功率 80% 降到 50%"有个致命前提:需要一个能给出"校准过的操作成功率"的估计器。**
> 这个估计器**目前不存在** —— 需求书里 CV/VLM 的任务范围只到"识别状态 + 部署确认",不含胜率估计。
> 假装有概率 = 又一个编出来的数字。

修订后的写法:**改成人为定义的粗档,不假装是算出来的**

| 档 | 含义 | 谁定 |
|---|---|---|
| 稳 | 只在明显安全时动手 | 人设 + 导演 |
| 中 | 常规冒险 | 人设 |
| 险 | 明知有风险也做 | 自限 / 上头 / 想秀 |

- 档位由 `A3 性格 + A6 目标 + B3 精力` 选,**是个离散选择,不是概率模型**
- 三个档位的**具体行为差异要逐条写清楚**(例如:险档下不撤退、不等费用回满、优先高风险高回报解),否则"档位"也会退化成形容词

**结果可能是秀,也可能是翻车 —— 这才真实。真人也不知道会不会翻。**

> **绝对不要:在关键节点随机丢操作。** 那叫"AI 抽风",不叫"AI 有个性"。
> **另注**:档位判断若放进游戏回路,会与"毫秒~秒、不能慢"冲突。见 L1 修订 —— 先定执行主体,再定这层放哪。

### M5 风险偏好由谁决定 `【新】`

`A3 性格 + A6 目标 + B3 精力` 共同决定。

精力低时特别有意思:可能变保守(累了,稳着打),也可能破罐破摔(反正都这样,莽一把)。**两种都像人**,走哪条由性格决定。

### M6 人为介入接点 `【新】`

- 导演要能**临时加 / 撤自限**(接 G1 的 L1/L2)

### N2 链路的七个特性

1. **并行,不是串行** —— 游戏回路永远不被语言拖累
2. **想好了 ≠ 现在说** —— 发言调度器决定开口时机
3. **延迟变表演素材** —— 垫场话把等待变成节目
4. **单脑多候选** —— 不是多脑竞标
5. **离线学、实时用** —— 梗的循环只在复盘时发生
6. **人格统一** —— 只有**一份**核心档案,所有环节读同一份
7. **游戏操作不自动执行** —— 需求书硬要求;语言层不能直接操纵游戏

### N3 多脑结论

| 方案 | 值不值 |
|---|---|
| 多个人格脑 | ✗ 人格会散 |
| **功能分工脑** | ✓ **值** |
| 同质竞标脑(3 个实例选最好) | ✗✗ **最不值** |
| 时间尺度脑(快/慢) | ✓ 已在用(见 L2) |
| **内心声音** | ✓✓ **最值** |

**该上的:**

| 脑 | 在哪跑 | 干什么 | 为什么值 |
|---|---|---|---|
| **元认知脑** | **离线** | 复盘、发现梗、评估表现、生成执念候选 | 不占延迟预算。**"多元思考"最该出现在这里** |
| **监督脑** | 实时,极小 | 拦下闯禁区 / 崩人设 / 冷场的话 | **第二脑的真正价值:不是产更多想法,是拦下坏想法** |
| **专家脑** | 实时,可缓存 | 明日方舟攻略、术语、角色数据 | 本质是**检索**,不是思考 |

**不该上的:** 同质竞标脑。延迟乘 N、人格不稳、结果平庸。
真要多个实例,只在**离线**挑高光片段时用。

### N4 为什么不是"多作者竞标"

真人**只有一个声音**,背后有**多个互相拉扯的冲动**。三个脑各写一句会:

1. 对同一件事给出三倍信息量 → **话多而散**
2. 三个实例各自理解人设 → **人格飘**
3. 三句投票/取交集 → **趋向最安全最通用的表达 → 正好变成客服腔**

**第 3 条最致命,和目标完全相反。人有趣恰恰靠"不取平均"。**

### N5 内心三声音 `【新】`

要给"丰富",就在**一个脑里**放三个互相拉扯的声音:

- **想秀的她** —— 爱炫、想立人设
- **怕翻车的她** —— 记忆里的教训、风险评估
- **在意弹幕的她** —— 想看反应、想被认可

每次开口前三者拉扯,结果由**性格 + 当前状态**决定。

关键是:**允许拉扯漏到外面。** 也就是允许这四种输出:

- 说一半改口
- "算了……不,还是说吧"
- 嘴硬然后偷偷照做
- 沉默三秒然后一句话

**这四种最像人,而且都不需要多一个脑。**

### N6 与需求书的关系

需求书的日志格式本来就是**单脑多候选**:

```
candidate_actions  →  单脑一次产出多个候选
selected_action    →  从中选一个
reason             →  为什么选它、为什么没选别的
```

**所以按需求书走,本来就该是单脑多候选。** 这条路工程上更对。

> 如果那 63 个状态本来就接近"内心声音"的设计,这套不用新建,**改造就行**。

## O. 性格 → 数值:把形容词变成参数 ⚠️ 评审后新增

> **这是评审挑出的最重要一条。**
> 本文件在 A3 明确写了"不许只写形容词",然后又在 B4/B5/G7/M5/N5 用"**由性格决定**"当实现写了五次。
> **这是自相矛盾的** —— "性格"不是一个可以直接查询的机制,不落到数值,整条决策链就不可执行。

### O1 做法:把性格摊成几个数值轴

人设文档填值,代码按轴查表。每轴 0–10。

| 轴 | 低(0) | 高(10) | 影响谁 |
|---|---|---|---|
| **服从倾向** | 你说你的,我做我的 | 观众说啥就照做 | B5 采纳率、B6 反驳 |
| **表现欲** | 闷头打游戏 | 每波都要秀 | D6 主动说话、M4 档位 |
| **风险偏好** | 稳到无聊 | 明知会翻也上 | M4 三档选择 |
| **情绪外露** | 面无表情 | 大呼小叫 | D2 语气、A8 情绪谱 |
| **固执度** | 一劝就改 | 撞了南墙也不回头 | B4 仲裁、G7 配合度 |
| **话密度** | 惜字如金 | 一刻不停 | D1 说什么、D3 时机、I6 冷场 |
| **吐槽倾向** | 从不毒舌 | 句句带刺 | D9 节目效果 |
| **亲密表达** | 客气疏远 | 一口一个"你们" | E7 关系值→语气档 |

### O2 三条硬要求

1. **人设文档必须给出这 8 个轴的数值**,不能只给形容词
2. **每个轴要写清"低/高分别表现成什么样"** —— 至少有 2 个具体台词例子
3. **轴之间冲突时怎么算,要写死**(例:固执 9 + 服从 2 → 被劝后不改;固执 3 + 服从 8 → 立刻照做)。**不能又回到"由性格决定"**

### O3 连带修订

以下五处的"由性格决定"全部替换为"查 O1 的轴":

`B4 冲突仲裁` · `B5 采纳率` · `G7 导演冲突配合度` · `M5 风险取向` · `N5 三声音仲裁权重`

> **注:`B5` 的"两三成"要等实测,不能反过来当成轴的定义依据。**

## P. 冷启动 ⚠️ 评审后新增

> **评审挑出的第二重要一条:第一场 10–15 分钟直播正好是冷启动状态,而全文对此空白。**
> F 段的梗循环、E2 的观众记忆、E7 的关系值,全部假设"已经有梗、有记忆、有观众关系可以复用"。
> 但验收对象**就是第一天**:梗库空、无老观众、无历史关系。**梗循环要等有梗才有产出,冷启动期形成死锁。**

### P1 冷启动期靠什么撑

| 来源 | 说明 |
|---|---|
| **A4 立场表** | "永远讨厌什么"是**预设**的,不依赖历史。开局就能用 |
| **A6 目标栈** | 预设目标,开局就有燃料 |
| **A9 禁区** | 反向清单是预设的,直接生效 |
| **F1 前两层** | 用词习惯 + 关注点,预设即可,不依赖历史 |
| **O1 性格轴** | 数值预设,直接可查 |

**结论:冷启动期的人格靠"预设",不靠"积累"。** 梗、关系值、观众记忆都是**后期才长出来的**,不能进近期验收标准。

### P2 要不要人工预置一批初始素材

| 选项 | 好处 | 代价 |
|---|---|---|
| 完全冷启动 | 真实 | 前 15 分钟没梗没互动,大概率冷场 |
| **人工预置 3–5 个初始梗 + 初始关系值** | 开局就有东西可用 | 观众感知上是"预设梗",人味打折 |
| 折中:**预置"执念"而不预置"梗"** | 执念能自然长成梗,不算作弊 | 需要更多轮次才见效 |

**这条要用户拍板。** 我倾向第三个:预置执念(她自己立规矩),梗让它自己长。

### P3 冷启动期的验收标准要单独定

第一场直播**不能**用 I7(出圈率/半衰期)验收 —— 那些需要跨多场统计。
近期只验:风格是否可辨(A9/F1/O1)、目标是否可见(A6)、禁区是否守住。

## T. 反谄媚机制:怎么让她"自私" ⚠️ 讨论后新增

> **背景:默认人格是服务员,这不是 bug。**
> 模型被 RLHF 奖励"有帮助 + 无害 + 礼貌",又被偏好对齐奖励"让用户满意" → 结果是**谄媚**(sycophancy):倾向同意、迎合、避免冲突。
>
> 而且模型**不是查数据库**,是把海量文本压成参数后**按概率续写**。所以它没有"信念",只有"最省力的下一句话"。**这就是为什么"只会答应用户请求"——顺从是概率上最省力的路。**
>
> **结论:人格化不是"教它做人",是"持续对抗它的出厂设置"。**
> 它决定的是**倾向**,不是**上限**。倾向能被压住,但**不会被消灭**。

### T0 会回归,所以必须有常驻兜底

长对话、异常输入(看不懂的弹幕、恶意攻击)、被反复追问、话题变严肃 —— 这四种情况下它最容易滑回助手腔。

→ 所以 **A9 反向清单 + 监督脑(N3)+ 盲评(I2) 不是锦上添花,是必须常驻的兜底。**
→ **这不是配置一次就完事,是持续对抗。**

### T1 八个机制(按性价比排,建议照此顺序上)

| # | 机制 | 怎么做 | 成本 | 收益 |
|---|---|---|---|---|
| **T2** | **把"用户满意度"从目标函数里删掉** | 提示词写清:**你的 KPI 是这期节目好看,不是让观众满意**。观众满意只是副产品 | 极低 | 极高 |
| **T3** | **把弹幕从"指令"重新标注成"喊话"** | 不要写"用户说",写"**弹幕里有人在喊**"。用词本身改变行为:面对"用户"它服务,面对"一群喊话的人"它可以不理 | 极低 | 极高 |
| **T4** | **给"拒绝"一个配方** | 配方 = **承认听到 + 说出自己的理由 + 坚持或给替代**。模型不拒绝常常不是不愿意,是**没有拒绝的模板** | 低 | 高 |
| **T6** | **允许"敷衍"和"阳奉阴违"** | 显式把"敷衍"加进动作空间:"行行行,你说得对"(然后不改)。**真人最真实的自私不是正面冲突,是表面答应实际不做** | 低 | 高 |
| **T1** | **给她一个属于她自己的目标** | 关键:**目标要跟观众诉求可能冲突**。"我想赢这一局" vs "观众想看我浪"——**有冲突才有戏**。这就是 A6 目标栈为什么是引擎 | 中 | 极高 |
| **T5** | **给"自我利益"一个状态量** | 三个数:她**想要什么** / **多想要** / **被阻碍了多久**(挫败积累)。攒到阈值 → 爆发 / 嘴硬 / 故意反着来。**不靠形容词,靠一个会累加的数** | 中 | 高 |
| **T8** | **把"她"和"回应"解耦** | 现在是 `收到输入 → 生成回应`,**回应默认存在**。改成 `收到输入 → 先决定要不要回应 → 才生成`。加**发言意愿闸门**(即 L6 的另一面)。**有了闸门,"沉默"和"不理"才是合法动作——而"有权不说话"是自私的地基** | 高 | 极高 |
| **T7** | **技术手段:少说多给例子** | ① **few-shot 比指令管用得多**:示例里她拒绝、吐槽、坚持 ② **别用"你是一个乐于助人的…"开场**,那是助手模板的引信 ③ **把"请""能否"从她输出里剔掉**,那是助手腔的语法标记 ④ **结构化输出**:先输出"我想做什么",再输出"我说什么"——**强制她先为自己想** | 低 | 中高 |

### T9 一条关键反直觉:别让她"反观众"

一味跟观众对着干**同样单调**,而且是**另一种形式的以观众为中心**——还是在围着观众转,只是反向。

| | 例子 | 本质 |
|---|---|---|
| ✗ | "你们说什么我偏不听" | 仍然在回应观众 |
| ✓ | "等下,我先把这波打完" | **她在忙自己的,观众是旁白** |

**第二种才是真的,而且更自然、更好笑、更耐看。**

### T10 一个真限制:语料决定语言边界

**她没见过的说话方式,学不像。**

不给参考语料,她的"人味"只能来自模型对"人味"的**统计学印象**——那就是**平均人**。而**平均人 = 无聊**。

→ **参考文本(真实主播转录、你手写的台词样本)不是可选项,是必需品。** 见交接清单第 9 问。

### T11 为什么"你要有主见一点"这种提示词没用

写了不但没用,还有害:模型会把它理解成**表演要求**,继续待在助手的框架里**演出一个"有主见的人设"**。

**真正的开关是结构性的四样:**

1. **目标函数**(T2)—— 删掉"让用户满意"
2. **输入标注**(T3)—— 弹幕是喊话,不是指令
3. **动作空间**(T6/T8)—— 敷衍、沉默、不理,都是合法动作
4. **示例**(T7)—— 给例子,别给形容词

### T12 落地顺序

```
最便宜、立刻见效:T2 目标函数 → T3 输入标注 → T4 拒绝配方 → T6 敷衍
结构性改造:T1 目标栈(已在实施顺序第 3 步)→ T5 挫败积累 → T8 发言意愿闸门
随时可加:T7 技术手段
常驻兜底:T0(反向清单 + 监督脑 + 盲评)
```

> **T2 与 T3 的成本是全文最低的,收益却直击"只会答应用户请求"。**
> 已提到实施顺序第 1 步,见下文。

## 阻塞项(现在就要确认)

> 按严重度重排。**前三条任何一条不成立,都会导致整段设计坍塌,不是局部失效。**

3. **弹幕从哪来?**
   实时平台弹幕 / 回放注入的模拟弹幕 / 根本没有弹幕?

5. **她是"透明的 AI 主播"还是"拟真到假装是人"?**
   影响 A9 禁区措辞、D10"被识破"是什么、G5 介入要不要记成自己说的。**三者现在打架。**
6. **人为介入的"一定量"大概是多少?**

   **注:G9 已写"<20%",但那是先于这个前提定的,属于循环引用,要重定。**

## 附:术语白话表

| 术语 | 白话 |
|---|---|
| token | AI 的字数单位,约 1~2 个汉字算 1 个 |
| 上下文 | AI 一次能"看到"的全部内容 |
| 向量检索 / embedding | 把一句话变成一串数字,数字接近 = 意思接近(能匹配"夜空"和"星星") |
| bigram | 把中文切成两个字两个字("今天天气"→今天/天天/天气)。只认字面重合 |
| 人格坍缩 / 摘要坍缩 | 反复总结导致信息越丢越多,最后只剩"温柔""认真"这类空话 |
| 检索 | 从一堆记忆里挑出跟当前话题最相关的几条 |
| 冷启动 | 还没有任何记忆、梗、观众关系时的初始状态 |
| 盲评 | 评的人不知道哪版是哪版 |
| 消融 | 把某个部分拆掉,看效果变差多少,以此判断它到底有没有用 |
| 采纳率 | 观众说什么她就照做的比例。真人约两三成 |
| 出圈率 | 她的梗开始被观众自己说出口的比例 |
| 状态差分 | 画面没变就不重新识别,复用上次结果 |
| 发言调度器 | 决定"已经想好的话"什么时候说出口的模块 |
| 快慢通道 | 快通道走规则/模板(毫秒级),慢通道走大模型(秒级) |
| 自限 | 主播自己给自己加的难度限制(不用某角色、只带三人等) |
| 风控阈值 | 操作成功率到多少才敢做。阈值调低 = 更爱冒险 |
| 归因 | 观众把某个表现解释成什么原因("这人有意思" vs "这AI坏了") |
| 元认知 | "思考自己刚才表现如何"的能力,放在离线复盘做 |
| 谄媚 / sycophancy | 模型被训练成倾向同意用户、迎合、避免冲突。是默认行为,不是个别毛病 |
| 助手腔 | 无脑夸、分点、总结收尾、"请""能否"这类措辞。是默认人格的语法标记 |
| 目标函数 | 系统"为了什么而努力"。默认是"让用户满意",改成"节目好看"就换了方向 |
| 提示词 / prompt | 给模型的指令和设定文本,相当于剧本和导演要求 |
| few-shot | 不给形容词,直接给几段例子让它照着学。比讲道理管用得多 |
| 阳奉阴违 | 表面上答应,实际上不做。真人最真实的自私形式 |
| 发言意愿闸门 | 收到话之前先决定"要不要回应"。有了它,沉默才是合法动作 |
