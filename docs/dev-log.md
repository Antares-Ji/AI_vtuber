# 开发日志

## 2026-08-16：SQLite 记忆底座

本次工程目标：

- 用 SQLite 替换容易损坏、难查询的 JSON 记忆文件。
- 保留旧数据，且让记忆可以被检查和删除。

这次改了哪些模块：

- `src/brain/memory.js`：SQLite 表、事务、迁移、用户记忆删除、状态统计。
- `src/brain.js`：允许测试时注入临时记忆数据库。
- `src/server.js`：返回记忆状态，增加本地删除观众记忆 API。
- `public/debug.html`、`public/stream.js`：显示运行状态，并提供统一的文字与语音输入。

你需要理解的理论：

- SQLite：一个文件就是数据库，但能安全地查询和事务写入。
- 迁移：旧 JSON 先备份，再一次性导入新数据库。
- 事务：一组写入要么全部成功，要么全部撤销。

下一步：

- 把记忆按用户、直播、关系、世界书进一步分层，并做检索预算。

## 2026-08-16：分层检索 v1

本次工程目标：

- 让回复只使用当前观众自己的记忆和相关角色设定。

这次改了哪些模块：

- `src/brain/memory.js`：关系等级、同观众本场对话检索、世界书选择。
- `src/brain/reply.js`：把受控检索结果组装进上下文。
- `src/brain/llm.js`：只把当前观众的近期互动交给外部模型。
- `public/studio.html`、`public/studio.js`：显示本次检索、记忆健康和大脑诊断。

你需要理解的理论：

- 检索不是“把所有记忆塞给模型”，而是在有限上下文中选最相关、最安全的信息。
- 关系等级由有效互动次数得到，它只是直播策略提示，不等于真实的人际关系判断。

## 2026-08-16：记忆系统 v4

本次工程目标：

- 把记忆升级为可隔离、可过期、可审计、可按直播场次归档的系统。

完成内容：

- 事实仅在观众明确自述时写入，并保存证据、置信度和有效期。
- 电话、地址、账号等敏感信息不进入记忆库。
- 用户称呼更新时，旧称呼标记为过期而非直接删除。
- 关系状态由本地规则维护，影响弹幕排序但不伪造现实关系。
- 直播场次可归档，旧场弹幕不会进入下一场的回复上下文。
- Debug 页显示检索策略和记忆审计时间线。
- `npm run test:memory` 覆盖 1000 次 SQLite 写入与完整性检查。

这次改了哪些模块：
