# 关卡视觉记忆与本地训练（2026-09-12）

已建立可扩展的图像记忆库，当前仅覆盖 EP00 的 0-1「坍塌」：10 张已目视核验画面，来自三次实战。保存阶段、来源实战、分辨率、图像指纹、干员与朝向、历史落点、失败表现、部署证据和两星结算。两星有漏怪不是成熟三星攻略。

## 记忆如何使用

`scripts/game_visual_memory.py` 提供 seed、query、add。seed 不覆盖已有记忆；add 按图像指纹去重，新画面标为未审核，不直接进入训练。数据及独立图片保存在 `runtime/vision/stage-memory/`。

检索采用32×20颜色布局距离，返回相似候选，而不是关卡识别置信度。画面比例明显不符时不返回候选。它尚不是语义向量库，也没有验证跨关卡区分能力。选人和方向选择会改变相机投影，不能从历史图直接复用坐标。

`src/vision/stage-advisor.js` 是供 VTuber 调用的本地分析入口，串联已有本地工作进程、记忆检索、纯千问/纯YOLO/协同三种模式。返回结构化建议、耗时和校验错误；错误建议置空，模块不发送鼠标。尚未接入直播主循环，也未成为自动作战控制器。

示例（在项目目录）：

```powershell
runtime/vlm-env/Scripts/python.exe scripts/game_visual_memory.py query --image runtime/vision/captures/arknights/_live-control.png --stage 0-1
runtime/vlm-env/Scripts/python.exe scripts/game_visual_memory.py add --image screenshot.png --stage 0-2 --phase battle --session next-attempt
node src/vision/stage-advisor.js runtime/vision/captures/arknights/_live-control.png hybrid
```

记忆中风笛90级朝右的落地有截图证明；原卡片、落点、方向拖动仅是该次相机状态下的观察。落地验证看方向框、费用扣减、可部署数变化和角色留在地图。失败经验保留，避免把消失的拖动预览当作成功。

## 实际训练结果

训练脚本：`scripts/train-stage-memory.py`。结果和权重：`runtime/vlm/training/stage-memory-v1/`。训练期间临时释放原千问进程显存，完成后恢复原完整 BF16 工作进程。

| 项目 | 数据与训练 | 结果 |
|---|---|---|
| YOLO11n游戏地标 | 3张训练、2张验证，按实战分组；先10轮，再从原权重训练60轮 | 10轮mAP50为0；60轮mAP50约0.501，但precision约0.00667，误报严重，不升级为默认模型 |
| Qwen3-VL-4B LoRA | 完整BF16基座，7张训练、3张验证，12步；实战1+3训练、实战2验证 | 阶段与落地状态联合完全匹配从0/3到0/3，未改善，不启用适配器 |

YOLO只标注红色入口与蓝色保护目标，没有敌人种类、干员卡片或可部署格类别。少量同地图验证不能证明新关卡泛化。千问验证集没有已部署正样本，无法衡量部署识别召回率。训练损失或保存了权重均不等于效果提升。

协同路径支持通过进程环境变量 `ARKNIGHTS_YOLO_WEIGHTS` 指定实验地标权重；未设置时保留通用YOLO。此次训练权重没有通过质量验证，因此默认不加载。千问微调适配器同样只保存，没有上线。

## 验证与限制

4项记忆测试通过：已有参考图检索、未知关卡过滤、画面比例过滤、实战数据分组。已实际调用三路本地分析新入口。首轮纯千问和协同都错误地将已部署风笛判断为未部署，并输出单数坐标，被校验器拦截；已补充明确的数组格式和观察状态约束。这是接通流程的测试，不能声称自主部署成功。

后续数据重点是更多关卡、不同视角、成功与失败部署前后成对画面、费用与占位状态、完整标注的敌人和部署格。新增样本需核验，不把模型自己的猜测当训练真值。真实动作闭环仍需在游戏内验证，不用静态图测试代替。

格式约束修正后再次实测，纯千问和协同都返回合法的observe/null建议，请求分别约3.40秒和3.74秒；但仍错误判断风笛未落地，因此只解决输出格式问题，没有解决视觉判断，也没有达到一秒响应。结果保存在 `advisor-vlm-v2.json` 与 `advisor-hybrid-v2.json`。此图本身已在记忆库中，不能用于独立识别准确率统计。
