# 歌唱能力架构与接入边界

## 1. 说话和唱歌是两条链路

```text
普通对话 -> 文本 -> GPT-SoVITS TTS -> 说话音频
唱歌请求 -> 授权检查 -> 歌词/音符/时值 -> 歌声合成引擎 -> 混音 -> 演唱音频
```

GPT-SoVITS 当前负责说话音色，不应被当作完整歌声合成器。唱歌需要音高、音符时值、呼吸、颤音和伴奏同步等额外控制。

## 2. 当前已经完成

- [provider.js](../src/singing/provider.js) 与普通 TTS 完全分开。
- `data/singing-catalog.json` 逐曲保存本地授权状态，不保存歌词；可提交模板见 [singing-catalog.example.json](../data/singing-catalog.example.json)。
- 歌声引擎、模型、音色授权和授权曲目齐全时，只会进入 `assetsReady`。
- 只有真正实现歌声渲染、播放和统一音频队列适配器后，能力状态才会变成 `ready`。
- 未就绪时，大脑必须诚实说明不会唱，不能用普通朗读冒充演唱。

## 3. 推荐后续实现顺序

1. 先用自有旋律和自写歌词做 10 至 20 秒短句，验证音高、时值和音色链路。
2. 选择专门的歌声合成方案，并确认模型、声库和输出用途授权。
3. 给授权清单加入曲名、权利人、用途范围、到期时间和凭证编号。
4. 做离线渲染、响度归一、降噪和伴奏混音。
5. 最后才接直播点歌队列、打断、取消和 OBS 音频路由。

不要把“拿到歌曲授权”等同于“拿到角色声库或音色模型授权”。曲词、伴奏、角色形象、声音模型和公开传播可能是不同权利。
