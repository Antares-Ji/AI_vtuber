# 杀戮尖塔 2 多模型代理研究设计 v0.1

日期：2026-11-01（America/Creston）。性质：探索性阶段总结与后续实验方案；不是预注册。用户目标：比较 Codex、DeepSeek、本地不同参数模型以及脚本/CV/原生键鼠路径，在 RTX 5080 上形成研究雏形。

## 研究问题与可检验假设

RQ1：在相同游戏观察和执行接口下，决策模型会如何影响有效动作率、战斗完成时间和存活？RQ2：固定决策模型后，4B/8B 本地视觉与云端视觉对字段可用性、观察耗时和闭环推进有何影响？RQ3：纯视觉路径的时间主要耗在推理、重复观察还是执行/恢复？

假设 H1：扩大视觉参数量可能改善部分信息提取，但未必降低端到端耗时。H2：减少无效悬停与重复观察可能比单独降低决策延迟更影响有效推进。H3：结构化观察能够降低感知负担，但引入额外信息，必须作为单独实验层。以上是待检验解释，不能用当前六例结果宣布成立。

## 因素定义

| 因素 | 条件 | 必须固定或记录的内容 |
|---|---|---|
| 决策 D | Codex 监督基线；DeepSeek；本地模型 | 精确模型标识、提示、记忆、思考设置、token 上限、人工介入 |
| 观察 O | 原始视觉；VLM+OCR；VLM+OCR+CV；结构化 API | 允许信息、裁剪、像素预算、坐标系、同帧校验、隐藏状态 |
| 执行 A | 原生 Win32；脚本/宏；游戏结构化动作 API | 一个决策能执行多少动作、回执及终止条件 |
| 本地容量 P | Qwen3-VL 4B、8B；后续候选另列 | 权重版本、量化、实际设备分配、显存、输出长度 |

脚本不是与 CV 互斥的条件：CV 负责观察/定位，脚本可以承载循环与执行。Minecraft Harness 的结构化状态和服务端回执不能作为 STS2 纯视觉结果。Codex 历史监督操作与无人自主 API 任务也不属于等价条件。

## 本轮已执行的实验设计

历史审计：回看既有记录，不宣称当时已预先制定此方案。单位为任务段、输入回执或保存帧；这些单位不能替代独立整局。

新增回放：固定六个已有困难样本（费用冲突、敌人信息、牌面类型、抽牌堆场景、遮挡生命、展开手牌），用现有只读观察代码执行 4B NF4、8B NF4 和 DeepSeek Flash 三个条件，每条件一次预热后每样本三次。预热样本不进入汇总。种子 20261101，只随机化各轮样本次序；模型顺序固定为 4B、8B、云端，因此仍存在时间/温度/网络顺序混杂。

使用专用 17656 端口，子进程内禁用缓存；生产观察源码不改写。运行前确认导演停止和空闲，通过原有 stop 接口确认释放完成；只发送保存图像的 read 请求。由本轮启动的观察/OCR 进程在 finally 中回收，不改变游戏存档、不产生新游戏动作。原来没有运行的服务在结束后恢复为未运行。

每请求保存：原图 SHA-256、来源记录、请求体、实际 provider/model/precision、耗时、生成 token、原始输出、规范化结果、OCR 校验、缓存状态、显存/利用率采样和错误。记录模型加载时间，单独于热请求统计。n=6 个选择性样本，每样本 3 次技术重复；不是 n=18 个独立样本。使用原生当前提示与相同 OCR 流程，云端仍有不同图像传输/服务商处理，不能声称只变更参数量。

没有独立人工标注，因此只报告 HTTP 完成、JSON/结构可用性、规范化失败、字段保留/未知与 OCR 一致性，不报告识别准确率。输出原文可能相同而延迟不同；重复结果保留。错误与超时进入失败分母，不静默剔除。

## 下一阶段分层实验（提案，尚未执行）

1. **离线感知集**：以固定游戏版本分层收集战斗、地图、奖励、事件、商店、结局等画面。建议先做 60 帧可行性样本，每场景 10 帧；这不是功效计算。独立标注牌名/费用/类型/规则、生命、能量、场景、可见目标和可达路径；困难例与普通例分别汇报。保留开发集与冻结测试集，不能在测试集上反复改提示后报告泛化。
2. **同观察决策集**：固定只含可见信息的观测 JSON 和历史长度，调用 DeepSeek 与本地模型生成动作提案，不发送键鼠。检查结构合法、目标有效、资源约束、理由与动作一致；策略价值由可复现游戏结果另验。Codex 历史基线单独报告，若新增 Codex 游戏决策需明确调整目前项目的 API-only 运行约束。
3. **小规模闭环**：先固定 DeepSeek 决策与原生执行，比较本地 4B/8B 与云端视觉；每条件从相同角色、难度、种子和起点开展配对试验。若重放存档不确定，改为同种子多局并记录路径分化。建议先每条件 5 个配对种子试运行，只用于估计方差和失败类别。按种子分块随机化条件顺序，每局从同一冻结记忆快照开始，不继承前一条件的经验。冻结规则记忆开关、历史效果与当前数值的标识方式、证据复用范围与过期阈值，并保存来源帧；当前最新历史版本使用了规则记忆和所有动作类型的证据帧复用，不能套用早期无复用协议。在线代码修复将该尝试记为开发中断，保留时间和原因；修复后另立版本与尝试，不拼成一次无干预成功。整局分母包括所有已启动的独立尝试，另报胜、负、剧情未知和中断，不从分母删除失败。
4. **脚本/CV消融**：固定模型和执行器，仅切换通用视觉定位与 CV 候选辅助。另设结构化 API 条件时明确标为信息优势条件；不得偷偷补齐视觉缺失字段。动作宏长度、规则记忆和重试上限均固定。
5. **容量扩展**：2B、其他中等容量或更大模型仅作为候选，先确认权重来源、许可、完整下载、显存与延迟；未安装模型写为未测试。当前只验证 4B/8B，不能填入不存在的 2B/14B/32B 结果。

## 终点与分析

| 层级 | 主终点 | 次终点 | 防止误解 |
|---|---|---|---|
| 感知 | 独立标注字段正确率、未知率 | 定位误差、p50/p95接口延迟 | OCR一致性不是准确率；未知与错误分开 |
| 决策 | 当前候选/资源约束合法率 | 重复悬停、目标理由矛盾 | 合法动作不是最优策略 |
| 战斗 | 完成战斗的总墙钟时间、完成比例 | 确认出牌/分钟、HP损失、输入重试 | 输入回执不等于生效 |
| 整局 | 通关比例、败北比例、到达层数 | 剧情/未知结局、中断比例、生存时间、成本、人工介入次数 | 中断按删失/中断报告；不当作死亡 |

有效出牌必须有动作后独立帧支持，例如能量变化和牌离手；敌人扣血/格挡另行核对。不把预测数值当作结果。结局判定先记录原始标题、生命、已完成首领与后续状态；预先以所研究游戏版本的明确通关条件及独立审核制定标签。“胜利……？”或剧情生命归零在规则未确定时保留剧情/未知标签，不仅凭0生命判败、不仅凭标题含胜利判通关。总耗时纳入截图、观察、决策、验证、输入、等待和恢复，另列开发停机。正式推断以独立种子/整局为单位；重复请求嵌套在帧内。小样本先给原始点和描述统计，功效分析待试运行方差估计后制定。若后续有足够配对样本，可预先选择配对差值置信区间并按种子/帧簇重采样；多因素比较需控制多重比较，不能挑显著结果。
