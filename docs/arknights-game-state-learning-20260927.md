## 目标收敛

后续大模型工作要直接回答游戏状态问题，为状态机与行动验收服务。首个可度量任务定为部署状态：`absent`（没有所选干员）、`selected`（卡片已选或拖动中）、`pending_direction`（已落格但方向尚未释放）、`confirmed`（画面证据确认落地）、`unknown`。把选中、落格预览与实际部署分开，尤其降低把未完成操作误判成成功的风险。输出结构化状态、置信/拒识与证据，不产出未经校验的点击坐标。之后再扩展暂停、战斗、技能就绪/已释放、结算等状态。

## 可复现的基线比较

以同一个按战斗/采集会话分组、按 SHA256 去重的冻结样本清单比较：

1. 规则基线：现有 OpenCV/模板/状态机证据，不训练，使用部署计数、姓名 OCR、费用变化、方向框及动作后截图等已实现信号。
2. 底座 VLM：同提示、同输出 schema、同图像尺寸的未适配 Qwen3-VL。
3. 微调 VLM：在同一数据与提示上评估适配器。
4. 若需要检测基线，再比较未训练 YOLO 与专项训练检测器；检测器输出仍只作状态证据，不能代替动作成功判据。

所有模型用同一测试集并报告总体准确率、各状态召回率/精确率、macro-F1、拒识率、把未确认误判为已部署的 false-success rate，以及每帧延迟。先固定数据划分和提示，再做前后配对比较。开发验证集可选 checkpoint；最终测试集只在模型与阈值定版后运行一次。样本不足时逐例报告置信区间或原始混淆矩阵，不强调小样本百分比。

## 抽帧与防泄漏

- 先由进关/结算事件切成单场战斗；同一场战斗、同一重试组和其派生裁剪永远属于同一 split。
- 用图像 SHA256 精确去重；再用感知哈希或视觉 embedding 聚类近重复帧。近重复簇整体放进同一个 split。
- 训练帧先做时间去相关抽样：以固定最小时间间隔、视觉变化阈值或状态转移事件取样。状态边界附近保留少量相邻帧作边界样本，但不跨 split；长时间静止重复帧降采样。
- 测试按完整战斗/会话留出，最好含未见采集时段或不同关卡。分组完成后才生成裁剪、增强和缓存，避免衍生物泄漏。
- manifest 记录原录像、战斗ID、帧序号/时间、SHA256、近重复簇、状态标签、证据说明和 split。低质/黑帧/不完整操作转移标为 unusable 或 unknown，不默认为负例。
- 每个类别由人工核验动作前、中间态和动作后状态。状态需有可观察定义；必要时标记不确定，保留原始失败证据。

## Checkpoint 与训练记录

后续训练继续保存每步或固定间隔训练 loss、验证集状态指标、训练/验证 split 清单哈希、优化器/随机数状态、学习率、耗时、资源、依赖版本、基座/适配器校验和。定期 checkpoint 同时保存 optimizer 与 scheduler 状态，支持真正续训。保留 `best-by-validation` 与 `last`；独立测试指标、预测和逐例错误另存，不能以训练 loss 代替验证表现。每个 run 有唯一目录，不覆盖历史产物。

## 硬件选择

新增训练脚本不指定 `device=0`。让训练框架自动选择 CUDA/CPU，或将设备作为可选参数由调用者明确设置；多任务协调器避免同时把同一设备分配给彼此争抢显存的任务。记录实际采用的设备，但设备选择不改变数据划分、优化步骤和评测口径。

## 决策门槛

先完成近重复审计和战斗级 split，再建立规则基线/底座模型基线。只有当独立测试上部署 false-success 下降、关键状态召回足够且多关卡复测稳定，才讨论把模型并入游戏状态服务。训练数据规模扩充应优先补状态转移与失败案例，而不是增加同一静止画面的相邻帧。任何新权重都不直接覆盖当前生产权重。
