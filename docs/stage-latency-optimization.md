关键问题仍是把敌人、预览或其他元素当作已部署干员。快速入口保持可选，完整入口的默认行为未切换。不到一秒的状态推理不等于不到一秒完成可靠操作。

## 调用

```powershell
node src/vision/stage-advisor.js runtime/vision/captures/arknights/_live-control.png hybrid --fast
node tests/vision/test_latest_frame_analyzer.js
runtime/vlm-env/Scripts/python.exe tests/vision/test_stage_memory.py
```

VTuber集成可调用 `createRealtimeStageAdvisor({maxAgeMs:1000})`，提交 `{imagePath, capturedAt:Date.now()}`。只保留一张待处理画面，替换旧请求；过期结果标记为dropped，调用方不能拿它执行动作。正在GPU上运行的推理不会被该调度器中断。该组件尚未接入直播主循环或连续屏幕采集。

训练继续可行，但优先收集“空地图→选人→拖动→方向框→确认落地→攻击”的成对证据，覆盖失败释放、遮挡、不同角色和地图。训练与独立验证按完整实战和关卡拆分；用真实目标检测、落地识别与端到端成功率决定是否启用新权重。单纯增加现有少量图片的训练轮数不能解决实时性。

下一项主要延迟仍在现有控制器的进程启动、动作等待和后验确认。此前控制请求约数秒，尚未完成常驻输入与战斗闭环优化。未来应让快速识别负责当前状态、详细模型按需决策，并用动作后的变化核验成功。
