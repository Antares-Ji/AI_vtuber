# AI 主播 / AI 桌宠实时交互系统架构 v1

## 目标

构建低延迟、可打断、全双工、支持本地与云端智能分流的 AI 主播系统。核心结构是“本地实时层 + 智能路由层 + 云端深度推理层”，避免所有请求无差别地交给云端大模型。

当前硬件：RTX 5080 16GB 台式机作为长期在线主节点；RTX 5070 8GB 笔记本作为可随时加入或退出的可选计算节点。两张 GPU 不做显存物理合并。

## 目标数据链路

```text
麦克风
  → 本地 VAD / Barge-in
  → 本地流式 ASR
  → Qwen3.5-4B
  → Router
      ├─ 简单问题 → 本地 Qwen 流式回答 → GPT-SoVITS 流式 TTS → 播放
      └─ 复杂问题 → 本地人格化过渡语
                    + 后台云端 DeepSeek/GPT 流式回答
                    → GPT-SoVITS 流式 TTS → 播放
```

用户开始说话时，Orchestrator 必须立即停止当前音频播放，并取消当前 TTS、LLM 生成或标记旧结果失效，随后处理最新输入。

## 模块边界

- Realtime Audio：麦克风采集、播放队列、回声与设备状态。
- VAD / Barge-in：检测用户开口，触发全链路打断。
- ASR：本地流式语音识别，尽早提供稳定的部分文本。
- Local LLM：Qwen3.5-4B，负责轻量对话、人格维持、意图识别和路由。
- Router：根据复杂度、事实风险、时效性与本地健康状态选择本地或云端。
- Cloud LLM：DeepSeek 或 GPT，负责复杂代码、长推理、专业分析和复杂规划。
- TTS：GPT-SoVITS，本地流式合成与可取消播放。
- Memory：短期上下文、长期记忆及可审计的写入策略。
- Vision：独立的画面采集和《明日方舟》状态识别服务。
- Game Agent：把状态转为离散动作，不直接耦合语音链路。
- Orchestrator：会话 ID、取消信号、节点发现、健康检查、降级与指标。

## 双机策略

5080 主机必须能独立运行完整闭环。5070 节点通过有线局域网和 WebSocket 或 gRPC streaming 注册；在线时可承接 ASR、TTS、视觉或其他可迁移任务，离线时主机自动接管。节点调度依据健康状态、显存余量、排队长度和实测延迟，而不是固定绑定。

## 开发阶段

1. 麦克风 → VAD → 流式 ASR → 本地 Qwen → GPT-SoVITS → 可打断播放。
2. 完善本地/云端智能分流、云端 Token 流与增量 TTS。
3. 加入可插拔的 5070 局域网计算节点与自动故障转移。
4. 完善长期记忆，并加入《明日方舟》Vision / Game Agent。

首要指标：首音延迟（TTFA）、打断响应时间、端到端对话延迟。没有实测收益的微服务不引入。

## 2026-09-05 当前落地状态

- Qwen3.5-4B：`E:\Qwen3.5-4B`，NF4 4-bit，本地服务 `127.0.0.1:11435`。
- 简单聊天已自动路由至本地 Qwen；复杂请求已自动路由至 DeepSeek。
- 复杂请求已支持人格化过渡语和云端 Token streaming；本地与云端在首 Token 前失败时可相互降级。
- GPT-SoVITS、ASR 和本地 Qwen 可以在 5080 上同时运行。
- 浏览器已支持持续录音、RMS VAD、Barge-in、LLM/TTS 取消、PCM 边收边播，以及“自然首句 + 剩余全文”的门控 TTS 预取。
- 已有服务状态、统一启动、安全重启、TTFT/TTS/ASR/客户端语音指标，以及可视化延迟页面。
- 5070 已有经过认证的注册、心跳、TTL 下线与 5080 回退选择骨架；任务派发仍禁用。
- 视觉运行环境和 osu! 离线测试已恢复；《明日方舟》真实识别模型与 Game Agent 尚未实现。
- 尚未完成：原生 WebSocket 增量 ASR、统一 TurnPipeline/服务端取消树、5070 任务传输与在途重试、《明日方舟》真实数据评测和安全执行闭环。

一句话方案：5080 为常驻主机，本地 Qwen 负责快，本地 GPT-SoVITS、ASR 与 VAD 负责实时语音和双工，复杂问题自动升级云端强模型；5070 是随时可加入或退出的算力节点，最后接入视觉和《明日方舟》Agent。
