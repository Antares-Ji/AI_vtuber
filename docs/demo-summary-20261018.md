## 一、Flappy Bird 已完成什么

使用下载的 flappy-bird-gymnasium 0.4.0 游戏和其附带预训练 Dueling DQN，项目用 NumPy 推理，并增加36帧碰撞预判保护层。动作仍由真实环境执行；未修改得分、物理或碰撞判定。该模块不调用千问，不需要GPU或云API，也没有在本轮重新训练权重。

- 独立验收种子30000—30099：100局全部活着达到1,000分，共3,769,100环境步。
- 单局耐久种子40000：达到10,000分，376,691步，零碰撞。
- 原始预训练策略另组基准种子20000—20099：64/100局达到1,000分，36局碰撞。两组种子不同，不能表述为同种子逐局对照实验。
- 默认环境中无有限最终关卡。这里的“完成”指达到约定验收目标，不能宣称游戏已通关或永不失败。
- 10,000分测试是关闭画面的加速计算；约3小时29分钟是按30 FPS换算的游戏内时长，不是实机实时运行时长。
- 已有可见窗口运行证据；历史渲染图仅为截图，不是视频录像。

## 二、Minecraft 已完成与未完成

现有链路：用户目标/事实反馈 → Qwen3.5-4B规划 → 动作校验与调度 → Mineflayer → 真实世界观察；OBS虚拟摄像头接入网页，玩家可旁观 jiaobenbot。

本轮曾验证采木、制作工作台/木板/木棍/木镐、部分导航与采石操作；历史取得物品不等于停止时仍持有。75个动作是项目已封装接口数量，不是Mineflayer全部方法，也不代表75项都通过了实机验收。

尚未完成：安全房屋、床、箱子、火把、熟食与浅矿返家的一整套生存流程。不能展示为“已经能稳定自主生存”。

本轮暴露的实际问题：

1. 寻路底层开关与上层预检/时间预算曾相互冲突，导致采集导航被拒绝或超时；相关修复已有代码与测试，但复杂地形稳定性仍未获得充分实机证明。
2. 多次死亡导致库存丢失、阶段重做和旁观视角解除；空手应战和危险处理策略曾影响生存。
3. 模型长请求、取消未及时释放执行槽和503服务忙造成停顿；做过提示压缩、调度保护、诊断与异常引用清理，不能据此宣布全部延迟问题已解决。
4. 主动循环在16:02 UTC维护时停止。16:09 UTC恢复循环和采样器的组合命令被执行策略拒绝，没有提供具体原因；此后没有恢复千问规划。
5. 后续监督主要反复做健康检查，未解决启动阻塞，未形成新的建房成果。这是本轮未完成的执行问题，不应归咎为已证明的模型能力上限。

### 停止时状态

用户已明确STOP并要求只总结打包：自主循环 enabled=false、running=false，无主动任务；每分钟自动监督已PAUSED；三秒采样器已退出；机器人此前已断开服务器，未重新连接。观察里的生命/饥饿/位置是断线前最后值，不能当实时存活证明。后续不会自行恢复任务。

## 三、虚拟主播工程的展示口径

工程已有：原创角色“姬岁歌”的设定与人格资料、人格/情绪和记忆模块、LLM路由、SenseVoice语音识别、GPT-SoVITS/浏览器TTS、Live2D舞台、字幕与直播工作台，以及游戏观察/控制适配。

这些是仓库已有实现与文档记录，本次没有对所有模块重新做端到端验收。Flappy Bird目前是独立游戏AI演示，未证明已经与主播语音讲解完整集成。Minecraft页面截图中的角色模型是当时展示资源，不能据此宣称原创美术/模型制作已经完成。

没有已完成的“千问在Minecraft里强化学习更新权重”证据。当前运行反馈、规则调整、记忆和已有SFT/LoRA实验需要分别表述；本包不包含模型训练或权重更新的成果宣称。

## 四、为什么两种游戏效果不同

Flappy Bird提供固定12维观测、两个动作与明确碰撞反馈，任务范围小，且已有预训练策略和专门保护层。Minecraft需要长期任务保持、世界探索、导航、交互、材料与配方、危险处理和多服务协同。当前证据说明两套系统的实现成熟度不同，不能只用“千问差”或“Mineflayer差”解释全部故障。
