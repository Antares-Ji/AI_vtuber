# 尖塔结算后继续尝试

用户要求继续尝试、尽快通关，因此导演Skill增加显式参数`continueAfterDefeat`，默认false。设置为true只允许走完当前败北结算流程，最多三次经当帧视觉与OCR共同核对的“继续”“解锁”或“返回主菜单”点击；进入战斗、地图、房间、事件、奖励等新冒险场景立即清零。下一局结算仍停止。点击由DeepSeek角色选择，不由监督代理指定。

```json
{"skill":"sts2:native-play","args":{"maxSteps":300,"continueAfterDefeat":true},"allowLive":true,"timeoutMs":1200000}
```

只在0生命分数和败北文字同时出现时确认败北；不会仅凭0生命跳过胜利/剧情结局。结算标题字体导致OCR置信度稍低时，仅在明确的顶部“败北”文字、云端场景说明一致且0生命成立时接受。没有这一组合则保持未知。“继续”必须与唯一高置信度OCR文字位置关联，使用OCR文字中心而非视觉模型估计的近邻点。输入后必须重新截图，不能把回执当作已返回菜单。

首次试验发现两项流程问题：粗略视觉落点在按钮文字上方，点击未推进；改用已关联的OCR文字中心后进入统计/解锁页。一张死亡结算包含多页，单次点击限制过严，现按最多三次的结算流程限制。未知结算可做最多三次只读重观察等待动画结束，不发送猜测动作。相同画面的重复动作保护保持有效。

一次实际云端观察返回JSON后附加文字，导致格式错误。现在仅对模型返回的非法JSON/对象格式做一次相同图片的只读重试；HTTP错误、取消和未完整返回仍失败，不提取局部JSON冒充完整结果。格式重试不发送键鼠输入。

验证：自主循环、云端传输、Skill运行时和输入接口87项通过；结算OCR6项通过。覆盖默认停止、仅允许核对按钮、最大三次、进入新冒险撤销、模型不能自授权限、低置信度与歧义文字拒绝、JSON重试上限。Skill目录已重新生成。实际新局推进结果另见任务日志，测试通过不表示通关。
