# Open-source foundations for physical Dou Dizhu

**Review date:** 2026-11-22. **Decision:** Use classical vision, DouZero rule helpers and a model-matched robot SDK for the fixed-tray MVP. Use LeRobot to collect tabletop trajectories and evaluate learned manipulation when the task expands to variable poses or loose cards.

## Scope and method

This targeted review asks which public artifacts can support playing-card recognition, legal move selection and physical card handling. It checked original GitHub repositories, official project pages, model cards, SDK documentation and the arXiv records for the two Robbyant reports. It included public source, downloadable checkpoints and reproducible examples with a plausible tabletop use. It excluded secondary-only announcements and treated simulation and demonstrations on other hardware as evidence for those configurations. Search phrases included `Ant Group Robbyant LingBot Touch official GitHub LingBot-Touch code tactile`, `Robbyant LingBot VLA 2.0 LingBot-VLA-2 github official open weights`, `GitHub playing card detector OpenCV MIT licensed rank suit`, `GitHub Dobot Magician Python SDK suction cup`, `Physical Intelligence openpi github official license` and `Hugging Face LeRobot SO101 official hardware ACT train record dataset policy`. The repository documentation and listed artifact metadata were reviewed. No papers or model checkpoints were downloaded for this review.

## Algorithm and validation

1. Keep a vision observation for each card with face identity, slot and classification score. Normalize each image patch with a fixed camera calibration. Compare deck-specific rank and suit templates and reject weak or ambiguous matches.
2. Use DouZero helpers to classify the public move, enumerate moves from the AI hand, and filter for legal responses including special moves, with explicit turn and pass handling. Convert chosen ranks to unique occupied slots. Store the move as pending until every physical card is verified.
3. Execute a fixed sequence from approach to pick, lift, verify and place. Validate visible card identity and single-card count at the verification station. Commit the batch to the game state only after matched card placement. Emit the committed event to the existing Live2D and speech layer.
4. Log camera observations, target slot, arm state, vacuum command, measured outcome and failure reason. A follow-up test can compare the fixed controller, ACT and a post-trained VLA on single-card success, double-pick escape rate and cycle time, with held-out pose and lighting conditions. A tactile model belongs in the gripper experiment if contact sensing is available.

The local smoke check used DouZero source at commit `718a5c9` and called the rule modules in isolation. It confirmed that a pair of nines beats eights, the same hand produces no higher pair against tens, and the two jokers are classified as the king bomb. Those checks did not cover the complete rules engine, camera or physical arm. No compatibility or reliability claims are made for untested hardware.
