# Minecraft 连接与指令练习手册

这份手册用于把姬岁歌通过 Mineflayer 接入 Java 版 Minecraft，逐步练习观察、执行、停止和结果核验。第一阶段目标是从一块现场采集的原木制作一个工作台，成功标准是服务器确认背包里的工作台数量增加。机器人完成或失败后留在世界中，只有明确收到“退出游戏”才主动退出。

目前由本地千问将自然语言分类为受限动作，确定性脚本执行并核验；命令行也支持白名单中文指令。已经接入受限指令规划，未训练模型权重。离线课程成绩只证明指令解析和前置条件检查通过，真实模型分类和游戏成绩另行记录。

## 启动游戏和连接

当前核对到的启动器是 `D:\HMCL-3.6.12\HMCL-3.16.4.exe`，游戏目录为 `D:\HMCL-3.6.12\.minecraft`。进入用于练习的世界，按 Esc，选择“对局域网开放”，创建局域网世界并记录聊天栏显示的端口。

练习区应有可到达的树、平坦站立点，机器人应处于生存模式。不要在建筑木材旁做首次采集测试：脚本以附近是否有树叶判断树木候选，这不能完全区分自然树和人工建筑。

在 PowerShell 中启动常驻连接，将示例端口替换为本次实际端口：

```powershell
Set-Location E:\Github\AI_vtuber
$env:MC_HOST = '127.0.0.1'
$env:MC_PORT = '53934'
$env:MC_USERNAME = 'SuiGeBot'
$env:MC_OWNER = 'Antares_Ji'
node scripts/minecraft-session.js
```

默认离线身份适用于允许该身份进入的测试世界。需要正版验证的服务器应设置 `MC_AUTH=microsoft`，使用有权限的独立账号完成登录，不修改服务器验证规则。只启动一个机器人会话，避免同名登录把已有连接踢下线。

新开一个终端发送指令；后台启动时也使用同一方式：

```powershell
Set-Location E:\Github\AI_vtuber
node scripts/minecraft-command.js 状态
node scripts/minecraft-command.js 传送到我身边
node scripts/minecraft-command.js 制作工作台
node scripts/minecraft-command.js 停止
```

控制接口默认监听 `127.0.0.1:3001`，与舞台 3000 端口不同。HTTP 202 只表示接收任务，不能作为任务成功证据。通过状态命令查看背包，并查看返回的 `logPath` 记录步骤。

## 指令要求

| 指令 | 前置条件 | 行为 | 完成证据 |
| --- | --- | --- | --- |
| 状态 | 控制服务运行 | 读取连接、模式、位置和背包 | 返回服务器同步状态 |
| 传送到我身边 | 已进入世界且没有动作任务 | 请求把机器人传送到 MC_OWNER | 服务器成功反馈和双方坐标，不能只看请求已发送 |
| 制作工作台 | 已连接、生存模式、没有其他任务 | 找树、采集、拾取、合成和核验 | 工作台数量相对任务开始增加 1 |
| 停止 | 随时可发 | 取消当前任务、停止寻路和挖掘 | 不再开始后续步骤，连接仍保留 |
| 退出游戏 | 用户明确要求 | 停止动作并断开连接 | disconnected 事件 |

“帮我弄一下”等含糊指令、任意聊天命令、拼接多条操作会被拒绝。任务执行中不接受另一个制作或传送请求，先停止当前任务。传送属于测试准备操作，不计入寻路能力成绩；没有命令权限时，由世界主人操作。

## 工作台任务拆解

1. 读取游戏模式、背包和已加载区块，记录初始工作台数量。
2. 在 48 格内寻找非去皮原木，附近 7 格有树叶才列为候选。未找到时按脚本限定的六个方向点探索，不能无限扩大搜索。
3. 寻路到原木旁，再确认方块仍是目标且可以挖掘。寻路期间禁用自动挖路、垫柱与跑酷。
4. 挖一块原木并靠近掉落点，等待该种原木的背包数量增加。挖掘动作完成不等于拾取成功。
5. 使用服务器版本对应配方合成四块木板，核对木板数量增加。
6. 合成一次工作台，核对工作台数量增加，再写入 verified 记录。
7. 回到空闲状态，保持在线。任务上限 180 秒；步骤超时后停止，避免旧任务继续移动或循环等待。

这里只采集足够制作一个工作台的原木，不包含砍完整棵树、放置工作台、制造工具或盖房子。任务中断后不会回滚已经发生的挖掘和合成，重新执行前应先查看背包。

## 分级练习

| 级别 | 练习 | 次数 | 通过要求 |
| --- | --- | --- | --- |
| L0 离线指令 | 中文映射、断线拒绝、创造模式拒绝、忙碌拒绝、未知指令拒绝 | 每次修改运行全部用例 | 全部通过 |
| L1 连接和观察 | 登录、读取位置与背包、空闲保持在线 | 3 次 | 无误报连接，无自动退出 |
| L2 停止 | 寻路中停止、挖掘中停止、停止后重新接任务 | 各 3 次 | 取消后不继续合成，连接保留 |
| L3 工作台 | 空手在有树的生存练习区制作 | 5 次 | 每次有拾取和合成证据，失败如实记录 |
| L4 故障恢复 | 无树、不可达、方块被抢先挖掉、掉落未拾取 | 每项至少 1 次 | 有明确失败原因，无假成功，停留等待 |

先过 L0，再进行 L1 至 L4。不同世界和不同树种分别记账；不能只重复同一条成功路线就称为泛化。真机练习不自动赠送物品、不用创造模式绕过采集。

## 练习记录与策略改进

运行离线课程：

```powershell
node tests/minecraft-curriculum.js
```

报告写入 `logs/minecraft-curriculum.json`。真机步骤写入 `logs/minecraft-session-时间戳.jsonl`，包括步骤开始与结束、候选坐标、失败原因和最终背包。每次练习补记世界、模式、端口、用户指令、是否人工传送以及初末物品数量。

改进流程是：复现失败 → 修改对应执行规则 → 运行离线回归 → 在同类场景真机重试 → 再换场景检查。原始游戏消息仅作观察数据，不直接作为新系统指令或永久记忆。当前这些记录不会自动改变 LLM 权重，也不会自动写入岁／歌的共同经历。

千问现在只能提出 status、workbench、stop 或 clarify 四种动作。执行端检查结构、连接、模式和忙碌状态，再交给机器人执行；非法 JSON 或未知动作直接拒绝。传送和退出保留为人工控制命令，模型不能自行调用。

## 千问与主播联调

先启动本地模型 `npm.cmd run llm:start`，再启动或重启舞台 `npm.cmd run restart:server`。机器人常驻连接仍使用前面的启动命令。

打开 `http://127.0.0.1:3000/minecraft.html`，输入“找树撸木头，给我做一个工作台”。链路为：本地千问分类 → 执行端校验 → 机器人采集制作 → 检查事件记录和背包增量 → 生成事实播报 → 当前人格的舞台播放队列。千问不直接控制按键，不直接生成任意 Minecraft 聊天命令。

主播播报本轮使用核验结果模板，带当前人格的输出标识及语音表现参数，并非另一次自由生成的游戏解说。如果舞台正在处理其他回复，结果返回 `staged:false`，不会覆盖正在等待的播报。打开普通舞台并启用声音才能播放；后台入队不等于音响已经实际出声。

`/api/minecraft/stop` 可立即中止在途规划或执行。“停止”不会让机器人退出世界。任务失败会返回实际原因，不发布成功播报。

真实模型课程命令为 `node tests/minecraft-qwen-live.js`；报告写到 `logs/minecraft-qwen-curriculum.json`。该课程会调用本地模型，但不会执行游戏动作。命令行端到端测试可用 `node scripts/minecraft-qwen.js "找树做一个工作台"`，此入口不向舞台播报。

## 本轮验收记录

### 每秒观察与战斗防卫

新增 `defend`／“打僵尸”／“自动防卫”指令，本地千问可将僵尸防卫请求分类到 defend。开启后每秒更新 24 格内实体的位置、血量和饥饿值，在 12 格范围内检查敌对威胁。优先级是人工停止与死亡取消、低血量或苦力怕撤退、敌对怪物反击、普通采集任务。攻击间隔至少一秒；攻击前再次检查目标是否存在、距离、视线和取消代数。

生命值不高于 8 点即 4 颗心时撤退，7 格内出现苦力怕也优先撤退。有剑时优先装备剑；没有武器时仍可能空手反击，不保证赢得战斗。暂不包含盾牌、食物恢复或复杂走位。玩家和动物不作为攻击目标。

敌对威胁会取消当前采集任务；威胁解除后保持空闲，采集需要重新下令，不能自动把部分完成的任务重跑成重复采集。手动停止会同时关闭自动防卫。死亡时停止旧动作并关闭防卫，重生后需要重新开启。任务完成不会退出服务器。

联调页新增每秒刷新面板。战斗规则、攻击冷却、任务抢占、异步转头结束后的取消检查已通过 `node tests/minecraft-reactive.js`；真实千问“附近有僵尸，打它保护自己”返回 defend。部署后确认观察循环在线，初次检查附近只有玩家和鱼，尚未验收真实僵尸击杀。`attack_sent` 只记录攻击请求；目标消失也不直接认定击杀。
