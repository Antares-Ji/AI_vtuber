# 键鼠与帧率验收 V2

当前真实验证：重启主服务后，5秒只读诊断收到32次原始鼠标回调，目标游戏不在前台，未产生游戏操作。不能据此宣布按钮、键盘、滚轮或30fps通过。测试脚本不注入操作。

## 最小人工验收

先打开新版视觉页、共享窗口、开始自动采集，再切到真正的明日方舟客户端；浏览器视频不透传输入。不要在录制期间输入密码或进行购买、抽卡等有代价操作。

| 项目 | 通过标准 | 当前状态 |
| --- | --- | --- |
| 左/右/中/侧键X1/X2 | 每种实际具备的按钮各按3次，每次一对同input的down/up，顺序与次数吻合 | 待真人测试 |
| 鼠标移动/拖动 | 悬停轨迹有hover；按住移动有move，返回原点仍能判拖动 | 原生轨迹待测；规则测试通过 |
| 滚轮 | 上下各3格有wheel正负delta；横向滚轮有则另测，不能无硬件也标通过 | 待真人测试 |
| 键盘 | 选不会消耗资源的按键，短按、长按、组合键分别核对down/repeat/up；每个键独立配对 | 待真人测试 |
| 连拍30fps | 安全控件连续按住/拖动10秒，视频不同时间戳采样约30fps（建议至少28fps），最大间隔不超过100ms；保存帧数与报告一致 | 未验证；统计公式测试通过 |
| 窗口隔离 | 切到浏览器/其他应用，不得保存其键值和鼠标坐标；当前手势取消 | 待真人测试 |
| 左侧导航关系 | 点击左侧标签，前后帧父分组与右侧内容对应，标navigation-candidate；人工核验后才确定跳转 | 候选规则已实现 |
| 滚动关系 | 同页滚轮优先列滚动候选，仅重叠验证通过才拼图；不能把不同标签拼一起 | 模拟滚动测试通过，真实待测 |

系统保留键、Fn及未向Windows暴露的硬件键不能保证被钩子捕获。30fps是目标，不是已完成指标。截图重复的视频时间戳不能计为不同视频帧。输出目录runtime/vision/interactions；manifest.frameMetrics提供连续按住段的captureFps/sourceFps/maxGapMs，outcome指出零事件、零帧和不完整操作。
