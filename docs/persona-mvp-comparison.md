# 人格化清单与 MVP 对照

## 一句话结论

MVP 提供可运行的通用人格、情绪、记忆和安全底座；产品侧清单补充了游戏直播里的目标冲突、发言时机、导演协作和节目复盘。应把清单作为直播人格层的扩展需求接到现有底座上。

## 能力对照

| 领域 | MVP 已有设计/源码 | 人格化清单新增重点 |
|---|---|---|
| 人格 | 角色包与通用大脑分离；34 维稳定人格影响反应；情绪/关系只调节本轮表达 | 身份、矛盾点、边界、缺陷、立场、目标栈、参考语料；另提出 8 个节目性格轴 |
| 情绪 | 63 维动态状态，包含核心情感、事件评价、离散情绪、社会关系、动机和调节；按事件更新并衰减 | 将情绪接到游戏局势、观众建议、挫败积累和表现动机；要求写出稳定状态转换 |
| 记忆 | SQLite 分层存储、检索与冲突处理；长期记忆候选带观众原话证据并经人工审核 | 观众记忆、梗库、梗的冷却/退役，以及直播后离线复盘 |
| 决策 | 导演层分类回复意图、控制回答预算、选择主动话题；输出有安全策略检查 | 主播目标与弹幕建议仲裁；允许拒绝、敷衍、沉默；加入说话时机调度 |
| 人类导演 | 已有导演指令入口和策略边界 | L0–L4 介入分级、预览面板、紧急刹车和介入日志 |
| 评测 | 自动行为/情绪/记忆检查与真人盲测方案 | 节目效果、冷场、复读、采纳、介入率和梗生命周期指标 |

## 双方长处与短板

### MVP 的长处

- 分层明确，能把角色设定、稳定人格、事件评价、短期情绪、记忆、导演和安全策略分别维护。
- 记忆治理已考虑证据、审核、冲突、删除与隐私；比单纯把历史压成提示词更适合长期运行。
- 有源码、运行状态、工作台和自动检查，能直接成为后续实现底座。

### MVP 还缺的

- 多维人格/情绪不会自动变成鲜明的节目目标，也不会自动决定游戏时何时解说、何时沉默。
- 现有互动更偏通用聊天；梗发现、节目节奏和直播导演的时序控制还不成闭环。
- 自动化检查证明规则能运行，不能单独证明台词有趣或像同一位主播。

### 产品侧清单的长处

- 把“有主见”具体化为目标、取舍、拒绝、不回应、自限和失败后的反应。
- 把说话时机、游戏操作窗口、导演介入和直播复盘放进同一设计。
- 能识别自身假设未验证，并列出操作主体、机器、弹幕来源等阻塞问题。

### 产品侧清单还缺的

- 目标栈、挫败积累、三声音仲裁和发言闸门仍需明确字段、公式/规则、状态持久化和失败路径。
- O1 的 8 个轴与现有 34 维画像有重叠风险；应说明映射或证明必须新增，避免同一性格被两套参数拉扯。
- 弹幕复读和密度只能作为反馈信号之一，受在线人数、平台延迟和观众习惯影响，不能直接等同于笑点或梗成立。
- 节目段落、15 分钟样例和量化指标目前仍是提纲，需补具体流程、观察窗口、分母、基线和验收门槛。
- 游戏执行主体、直播机器和真实/模拟弹幕等前提未定时，双回路、硬实时和资源分配图只能视为方案假设。

## 建议的衔接方式

1. 复用现有 34 维人格与 63 维情绪引擎，不再另起一套情绪底座。
2. 在其上增加直播专用状态：当前节目目标、自限规则、候选表达、是否发言、可说窗口、导演介入级别和梗引用状态。
3. 决策顺序写清楚：事实/安全与紧急刹车优先，其次是游戏局面和主播目标，再考虑弹幕建议与表达风格。
4. 把“内心三声音”作为单一决策器里的候选理由，不要求三个模型分别生成台词；最终只选择一个可解释动作。
5. 先做一段可回放的 10–15 分钟样例；分别记录状态输入、候选动作、选中理由、沉默/发言、导演介入和弹幕反馈。
6. 用多名评审盲评与导演标注验证节目效果；弹幕复读只作为辅助数据。数据不足前不把采纳率或梗反应阈值写成事实。
7. 参考语料先落实授权、脱敏、标注和用途，再决定用于 few-shot、评测或微调。三者不可混为一种“训练”。
8. 观众记忆和梗库沿用项目的证据与删除治理，分别存储观众事实、观众说法、主播立场和直播事件。

## 需要先确认的前提

- 游戏操作由 AI、人类确认后执行，还是由人类完全代操作？
- 近期直播运行在哪台机器？哪些模型和服务实际可用？
- 弹幕来自真实直播、回放注入还是人工标注？时间戳和观众数量能否获得？
- 导演的介入频率和权限是什么？L4 刹车如何触发及恢复？
- 平台 AI 身份披露、观众数据保留、游戏画面/IP 和语音授权分别适用什么规则？

这些答案决定实现边界；在确认前，延迟预算、自动操作和观众反馈指标不能当作已验证能力。
