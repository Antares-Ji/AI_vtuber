# 0-7 本地视觉通关实测

2026-09-12，0-7「感染」最终三星通过：20/20 敌人处理完毕，生命保留 15，没有漏怪。最终结算截图和独立录屏均已人工复核。

执行顺序为伊内丝 → 风笛 → 琴柳 → 维什戴尔。前三人在蓝色目标前的中路地面形成防线，维什戴尔在上方中央高台朝左。部署数逐次 8→7→6→5→4；每次检查选中姓名、拖动后真实方向框、鼠标释放、待部署姓名和最终计数。伊内丝初次落地发生在补充方向阶段姓名校验之前，保留了原始前后截图与计数证据。

开战前，本地千问打开并读取了敌方情报的源石虫、士兵、机动盾兵，也打开了地图预览。初次地图判断漏读入口、误判蓝点位置并返回错误坐标格式，不能视为准确分析。放大图后识别出两个红色入口、一个蓝色目标，再单独核对蓝点在左侧。入口与蓝点之间的具体路线描述仍有错误；部署策略使用“先守蓝点前道路”的规则，并在实际战斗的绿色合法区域内重新定位，没有重放 0-1 地图坐标。

## 实际由什么执行

- 本地 Qwen3-VL-4B 完整 BF16：导航、情报及地图分析、编队部署顺序建议、卡片和落点提议、结算判读。
- 先前训练的 deployment-tray-v1 YOLO：先锋卡片检测，与头像匹配共同核对可用卡片。通用 COCO YOLO 也参与部分导航请求，但未找到目标时回退到纯本地千问；它不是游戏专用按钮检测器。
- 本地 OCR、颜色检查和几何检查：姓名、费用、部署数、绿色格内部与白色方向框；原生控制器执行鼠标及 Space 暂停。
- Codex 的作用为修改程序、检查错误和核验记录。战斗落点由本地模型提议并由本地绿色区域校正，没有通过聊天逐帧提供点击坐标。

## 必须保留的限制

这是一场在暂停辅助下、修复后续跑完成的三星战斗，不是首次启动就全程无人干预，也不是一秒响应验证。首次运行因暂停遮罩使绿色变暗而停止；随后遇到落点离绿色格过远、选中后头像模板不匹配，三次均停止在暂停状态后修正续跑。没有重新消费理智重开这场战斗。

本场没有按 E 释放琴柳回费技能，部署费用主要通过自然恢复等待获得。不能把上次 0-1 的技能回费证据套用到本场。没有启用代理作战，结算停留在是否保存代理阵容的提示，尚未选择保存。

暂停图绿色亮度阈值单独处理；落点允许在当前合法区域内有限距离校正并记录偏移。该校正只证明当前布局成功，不代表任意地图落点可靠。Space 操作及恢复逻辑使用已知暂停状态；更广泛的暂停识别和自动恢复仍需实测。

本次没有新训练 YOLO 或微调千问。新增战斗过程中候选结果必须经过审核才能成为训练标签。结束前追加的费用前缀 OCR 和普通战斗状态续跑分支通过语法检查，但没有再次实战验证，不能混称为本次成功路径。
