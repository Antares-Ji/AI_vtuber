# 独立录屏计时：实际部署延迟

2026-09-12新增 `scripts/record-game-timing.py`，独立Python进程，不调用VLM、YOLO、OCR或对象检测。只截取游戏窗口、编码录像、记录单调时钟和三个固定位置的像素变化。像素变化只是候选标记，不自动等同关卡开始或部署成功。

## 本次实测

录制目录：`runtime/vision/timing-recordings/1789184842816428100/`。

录到2720帧，实际持续137.57秒。目标20Hz；每帧保留捕获前后时间，画面底部烧录时间。AVI为固定帧率，若中途丢帧或窗口被遮挡，应使用烧录时间和timeline.jsonl，不直接用播放器位置作为实际耗时。

回看录像：T+63秒仍是关卡标题；T+64秒已出现战斗地图与HUD；T+65秒地图与卡片清晰。T+111秒仍在选择方向，T+112秒角色落地、费用扣减、部署数从8变7。

所以从战斗画面出现到第一个干员落地约48秒（本次人工抽帧核对界限约47至49秒，并非50ms精度的语义事件定位）。即使从清晰可操作画面T+65秒算起，也约47秒。包含助手调度、截图查看、工具等待、拖动与方向确认。不是千问推理耗时，也不是全本地自主控制测速。未进行暂停分析。

本次独立进程未读到有效鼠标按键边沿，录像中的LMB 0不能证明没有按下。可能与输入权限或注入路径有关，原因尚未确认；本次只以录像画面核验部署，不使用该按键字段计算拖动时间。脚本后续明确将按键轮询标为未验证。

这份记录证实实际部署存在几十秒延迟，不能用之前0.48秒局部推理替代。录屏工具已经可以记录并复核这一问题，尚未解决控制流程的延迟。

## 使用

从控制器status读取当前游戏窗口句柄后运行：

```powershell
runtime/vlm-env/Scripts/python.exe scripts/record-game-timing.py --hwnd 当前句柄 --seconds 180 --fps 20
```

录制默认有时限，不是后台无限监听。活动目录记录在 `runtime/vision/timing-recordings/active.json`；在该目录创建空的stop文件会正常结束并保存录像。游戏不在前台或被检测到遮挡时暂停采集并记录空档。
