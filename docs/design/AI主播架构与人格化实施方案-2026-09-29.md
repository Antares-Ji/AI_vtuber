# AI 虚拟主播架构与人格化实施方案

面向产品、人格、视觉、语音和直播集成成员的修订稿。以 2026 年 9 月 28 日两份组内 Word、仓库源码和交接文档为依据。

结论：近期应交付一段 10 到 15 分钟、有人类导演监督、能够按时间轴复盘的《明日方舟》主播样例。现有 34 维稳定人格、63 维动态状态和记忆治理可继续使用；关键改造在“先决定是否说与说什么，再进入安全检查与播报队列”。作品是否有趣须由独立盲评判断，代码检查只证明规则按预期运行。

## 一 交付范围与事实口径

| 类别 | 本稿采用的表述 |
| --- | --- |
| 已在仓库 | 通用人格与情绪引擎、SQLite 记忆与审核、双脑路由、TTS 和 ASR 接口、视觉工具与工作台。 |
| 设计中 | 主播目标栈、动作仲裁、合法沉默、发言队列、人类导演分级、梗的离线复盘。 |
| 待现场核验 | 明日方舟识别泛化、游戏操作主体、真实弹幕来源、运行机器与模型权重、角色资产与声音授权。 |

原总览中“自己玩游戏”、完成度百分比和固定延迟数字容易被读成已交付事实。本稿把它们改成待验证目标。组内文档提出的数值只用于实验起点，必须用同一台设备、同一场景测量后定门槛。

## 二 七层架构与唯一人物状态

| 层 | 输入与责任 | 输出或边界 |
| --- | --- | --- |
| 感知 | 游戏画面、时间、弹幕或回放事件；附置信度和时间戳 | 结构化局面快照；低置信度明确标记 |
| 人格 | 角色包、34 维稳定人格、63 维动态状态 | 唯一人物状态；长期倾向不因一条弹幕改写 |
| 记忆 | 已确认观众事实、主播立场、场次事件 | 可追溯检索；人工审核长期写入 |
| 决策 | 局面、场次目标、候选动作、导演信号 | 说或不说、理由、有效期与优先级 |
| 表达 | 获准的意图、风格约束、情绪摘要 | 可播文本与 TTS 意图；禁止越权声称能力 |
| 导演 | L0 至 L4 人工介入 | 预览、覆盖、静音与介入日志 |
| 复盘 | 录像、事件日志、人工评分、弹幕反馈 | 失败案例、语料候选、下一版参数建议 |

情绪的“愉悦、紧张、期待”等是状态描述；节目目标、是否采纳建议和是否发言是决策。两者相连，但不能把 63 个情绪量直接当成可执行动作。

## 三 人格与节目目标的接合

角色包写身份、价值、边界、说话样例和本场执念。34 维画像是长期来源，8 个节目轴只做派生视图，不另存一份相互竞争的性格真值。63 维动态状态只改变当前表达、风险感和注意力。

| 节目轴 | 建议来源 | 用途 |
| --- | --- | --- |
| 服从倾向 | independence、assertiveness、agreeableness、boundaryStrength | 建议仲裁；安全与事实永远优先 |
| 表现欲 | enthusiasm、socialInitiative、playfulness | 主动解说与展示欲 |
| 风险偏好 | openness、conscientiousness、emotionalStability | 仅在有能力估计和人工规则时使用 |
| 情绪外露 | selfDisclosure、enthusiasm 与当前调节状态 | 语气与表情幅度 |
| 固执度 | assertiveness、patience、reflectiveness | 坚持与复盘后修正 |
| 话密度 | extraversion、socialInitiative 与游戏窗口 | 发言频次上限 |
| 吐槽倾向 | humor、directness、boundaryStrength | 轻度吐槽，不攻击观众 |
| 亲密表达 | warmth、empathy、trustRate 与关系证据 | 称呼和距离，禁止假熟 |

以上仅是映射提案。实际系数需用样例台词和盲评校准。角色卡内的 0 到 10 数字属于初始提案，不代表从官方设定或真人样本统计得到。

目标采用“长期价值 → 本场目标 → 本局目标 → 当前窗口”四级。每个目标至少有 id、来源、优先级、有效期、成功条件和修改者。角色可拒绝观众建议，但拒绝必须能追溯到局面事实、目标或边界；不能为了制造戏剧性随机犯错。

## 四 先决定后表达的运行链

1. 感知层发布带时间戳、置信度和来源的局面快照。旧快照过期后不得作为确定事实。
1. 注意力调度先判断新事件是否值得打断当前目标；候选动作至少包含沉默、短反应、延后、回答、拒绝。
1. 轻量决策器选择动作并同步记录未选理由。只有选中“说”的动作才调用长文本生成；复杂争议可再走慢通道。
1. 文本通过身份、能力、隐私和版权检查后进入待播队列。队列项有 scene_id、deadline、interrupt_policy 和 cancel_token。
1. 游戏关键窗口、导演 L4 或新证据可使待播文本过期、取消或重新生成。只有真正播出的内容进入“她说过的话”的记忆；被丢弃草稿留在决策日志。
这条链解决原总览指出的工程冲突，同时避免默认每次都调用两遍大模型。简单场景用规则或本地短决策，复杂场景才增加一次规划调用。已有直接流式路径应保留为兼容模式，通过 A/B 样例比较延迟与节目效果后再决定默认路径。

## 五 三类时间与异常处理

| 通道 | 近期实现建议 | 观测方式 |
| --- | --- | --- |
| 局面与操作 | 先确定 AI 执行、人类确认或完全人工；当前按干运行与人工确认设计 | 识别延迟、过期快照数、误操作与人工纠正 |
| 即时反应 | 使用经审核的短句和规则；关键局可静音 | 事件到文本、文本到首包声音分别计时 |
| 深度互动 | 弹幕分批、目标检索、延后播报；无弹幕时由场次目标触发 | 队列等待、过期丢弃、p50 与 p95 |

断线重连恢复目标、情绪快照和待播队列版本；模型全挂时只用事先审核的短句并通知导演；TTS 不可用时转字幕或静音；弹幕洪峰时限流和批处理；直播中断时保存时间轴和未完成动作。所有降级台词按角色风格写，避免回到客服腔。

## 六 记忆与梗的闭环

继续使用现有证据、审核、冲突处理和删除流程。新增的“节目事件”与“观众事实”分开存。原始记录、索引标签、生成摘要也分开；摘要用于找回原文，不取代原文。对于项目总览提到的向量检索，先在固定查询集比较关键词、混合检索的正确率和耗时，再决定是否上线。

第一场冷启动使用预设立场、场次目标、关注点和经组内确认的台词样例。梗由离线复盘提出候选，记录出现时间、原话、局面、人工判断与适用情境；上线前人工审核，之后按冷却和退役规则使用。弹幕密度与复读可作为证据之一，不能直接等同于“观众觉得好笑”。

## 七 无真实弹幕时的等效验收

先做 20 个可回放的直播决策场景，区分它们与仓库已有课程回归场景。每个场景给定局面、角色目标、候选建议、预期可接受动作和失败条件。用真实弹幕、带时间戳的回放注入或导演人工事件三种输入之一运行；缺少真实观众时，不评“出圈率”和梗半衰期。

| 指标 | 定义与证据 |
| --- | --- |
| 角色一致性 | 盲评同一场景不同版本，按行为和台词分别评分；保留分歧记录。 |
| 目标可见性 | 评审能否从台词与动作指出本场目标；目标和事件日志可以核对。 |
| 动作可解释性 | 候选与选择理由在决定时写入；禁止事后补一段好听的理由。 |
| 沉默与冷场 | 沉默是合法动作；仅对超出节目计划、无局面原因的空白时段记冷场。 |
| 独立性 | 在有观众建议的场景计算采纳率，分母只含可执行且非安全冲突的建议。 |
| 节目效果 | 至少两位独立评审对趣味、节奏、非模板化表达盲评；报告均值和分歧。 |

通过线在录制前由组内冻结，先用基线版本测一轮，再确定改进幅度。现有 77 项情绪检查、32 条课程场景和 8 维盲评是底座证据，不能替代明日方舟 20 场景与节目效果盲评。

## 八 跨成员数据契约与顺序

| 接口 | 最小字段 |
| --- | --- |
| 视觉到人格 | schema_version、scene_id、timestamp、observation_ref、facts、confidence、stale_after_ms |
| 人格到语音 | utterance_id、text、emotion_intent、pace、pause、priority、cancel_token |
| 人格到导演 | candidate_actions、selected_action、reason、preview_text、deadline、risk_flags |
| 导演到人格 | level、operator、instruction、issued_at、expires_at、override_reason |
| 复盘事件 | event_id、source、goal_id、memory_refs、decision_latency_ms、outcome、human_override |

实施顺序：一，确定游戏操作主体、演示机器和弹幕输入；二，冻结角色卡与场次目标；三，补 20 场景和基线录像；四，接轻量动作决策与合法沉默；五，接待播队列及导演覆盖；六，接记忆检索和离线复盘；七，完成端到端盲评与性能报告。语音、视觉和人格字段应先共享一版 schema，再并行开发。

## 九 对原方案的改进意见

- 保留其最强的“目标驱动、允许沉默、冷启动、导演监督、离线复盘”主线，并把零散的 A 至 X 清单整理为一条可执行运行链。
- 取消没有方法学的完成度百分比；现状用源码证据、运行记录和未验证项表述。
- 把“弹幕是唯一客观反馈”“向量检索几乎零滞后”“两次调用必然延迟翻倍”等绝对结论改为可测假设。
- 把“嘴上答应、实际不做”限定为明确的角色玩笑，不用于真实承诺、导演命令或用户隐私操作；角色的自主性建立在可解释选择上。
- 把目前最大的人设空缺补成可供产品、语言、Live2D 共用的角色卡；相关草案见配套人物设计 Word。
