EXPERIMENT REPORT  /  01

杀戮尖塔 2<br/>多模型视觉智能体实验报告

RTX 5080 本机部署、4B / 8B 权重与云端参照的横向测量

| 实验范围 | 已完成规模 | 数据性质 |

| 本地4B、8B；云端Flash | 6个困难帧 × 3次 × 3条件 | 54次正式回放 + 3次预热 |

| 历史控制链路与任务日志 | 67个近期任务段审计 | 段数不等于独立游戏局数 |

摘要

本报告围绕杀戮尖塔2的截图观察、策略决策、原生键鼠执行与结果验证，整理项目阶段证据，并对消费级RTX 5080上的Qwen3-VL 4B、8B模型进行横向测量。官方DeepSeek Flash作为云端观察参照单列，避免把其延迟归为本机GPU性能。

在六个固定困难样本、每条件三轮且关闭缓存的回放中，4B、8B、云端的平均观察接口耗时分别为5.900、5.234和3.124秒。8B两类手牌输出共6次不符合接口要求；其较短处理路径也影响延迟。各条件均存在信息未知或场景分类限制，不能以JSON可解析或接口较快代替视觉准确率与游戏胜率。

主要发现

本地4B与8B均可在本机NF4配置下完成回放；参数增大没有自动消除接口与信息提取问题。下一步应固定观察、记忆和执行协议，再开展同起点闭环比较。

02  /  研究问题与比较边界

比较模型之前，先定义模型承担的职责、可见信息和动作接口。




“Codex跑”“DeepSeek跑”“本地模型跑”并非天然等价实验。模型可分别承担观察与决策；CV负责定位或核对，脚本承载流程，原生键鼠负责执行。若同时改变多个环节，结果只能描述系统组合，不能归因于某一个模型。

| 问题 | 目标量 | 当前能回答到哪里 |

| RQ1：容量如何影响本地观察？ | 同帧请求延迟、结构兼容、字段状态 | 已测4B与8B NF4；无独立正确率标签 |

| RQ2：云端能否减少观察等待？ | 同组样本的接口墙钟时间 | 已测云端Flash；不是等价硬件比较 |

| RQ3：整局能力由何决定？ | 有效动作率、战斗时间、通关/中断 | 历史证据与方案；未做同种子完整对照 |

已有系统条件

| 条件 | 决策 / 观察 / 执行 | 证据属性 |

| A Codex监督 | 对话代理 / 截图+局部Qwen / 原生键鼠 | 历史48层结算；有监督 |

| B DeepSeek结构化 | DeepSeek / MCP状态 / 游戏动作接口 | 历史接管；不是纯视觉 |

| C 混合本地视觉 | DeepSeek / 本地Qwen+OCR/CV / 原生键鼠 | 实机闭环推进与失败记录 |

本轮横向测量只替换观察条件，不调用规划模型，不发送游戏输入。历史Codex监督表现和结构化接口表现作为工程背景单列，不纳入54次回放的统计。

研究定位

SpireBench与AgenticSTS研究长程策略[1,2]；Cradle研究截图到键鼠控制[3]，SpireClimb开展视觉尖塔评测[4]。本项目当前切入点是消费级硬件上的混合架构、可追溯测量和分层失败诊断；“模型能玩游戏”本身不构成新颖性声明。

08  /  输出兼容性与可用性

HTTP完成、文本可解析、规范字段非空、字段正确和游戏成功是不同指标。




| 指标（每条件18次） | 4B | 8B | 云端 |

| HTTP返回 | 18 | 18 | 18 |

| 原始字符串可直接JSON解析 | 18 | 6 | 18 |

| 去Markdown围栏后可解析 | 18 | 18 | 18 |

| 规范结果非null | 18 | 12 | 18 |

| 缓存命中 | 0 | 0 | 0 |

8B的两类集成问题

12次输出包含Markdown代码围栏，现有解析器去除围栏后仍可处理；这与JSON内容错误不同。另有6次手牌输出采用顶层数组，而接口要求包含cards字段的对象。该结构差异触发规范化错误，parsed与ocr_check均为null；原始错误文本保存在E1。

计分解释

18/18规范结果非空不代表18/18识别正确。一个非空对象可以只包含未知生命，也可以保留不适用的候选目标。8B的12/18是本轮接口结构接受情况，不是66.7%的视觉准确率。

后续可单列“原样集成”与“仅格式适配”两套指标：适配必须固定规则、不改变牌名/数字/坐标，并重新记录处理路径和耗时。本报告保留当前原样接口结果，不把后处理补救偷偷计作原生成功。[E1]

失败分类建议

F1 结构不兼容：输出格式未满足接口约束。F2 信息缺失：字段不可见或不确定。F3 语义误读：牌名、费用或场景读错。F4 核对覆盖缺口：错误分类绕过对应校验。F5 闭环执行问题：动作虽提交但未推进。前四类可在回放中发现；第五类必须观察实机动作后的变化。

本轮发现，不冒充修复

云端抽牌堆menu分支保留候选，是值得后续回归验证的问题；本轮没有发送这些目标对应动作，也没有改线上逻辑。完整牌面的OCR核对字段为名称、类型、完整规则，费用不在此独立核对范围。

没有读取隐藏状态、没有由Codex手工指定新游戏坐标、没有利用过往结论填补未知字段。所有原文与规范结果保存在原始回放JSON。[E1]

4B文件约8.27 GiB，8B约16.33 GiB。加载时采用NF4，因此本轮8B在16GB级GPU上运行，无须将磁盘BF16文件原样全部驻留显存。实际显存还包括未量化组件、激活、KV缓存、CUDA上下文及桌面程序。简单的“参数量×位宽”计算不能替代测量。

资源结论的边界

图中虚线为16303 MiB总显存。请求后采样可能错过推理峰值；未记录进程独占峰值、持续功率曲线或整局电耗。云端本机约4 GiB占用不是云端模型显存，更不能据此称云端模型比4B更省GPU。

本机探针记录CPU为Ryzen 9 9950X3D、16核32线程，可见内存约47.15 GiB。该硬件信息为本轮只读补充，不用于事后推断当时CPU利用率、热状态或内存峰值。2B、14B、32B等容量未执行，不填入预测性能。[E2,E3]

输入耗时与有效推进需分开

同一早期快照中273个输入回执的物理动作合计351.19秒，均值约1.29秒。规划包含199次hover和52次drag，其中15次drag只做起点准备。键鼠动作时间短，不代表整个控制循环高效。串行观察、反复悬停、状态恢复和监督开发均会放大墙钟时间。

最新版本增加了历史规则记忆与动作证据帧复用；因此不同日期表现还混入协议变化。当前统计截止是历史日志时间，而非对现场状态的实时监视。[E4]
