# AI 主播一个月工程

## 工程目标

把当前“能互动的本地原型”推进为可持续训练、可解释、可恢复、可评测的角色系统。完成标准不是功能数量，而是每个模块具备数据边界、失败恢复、自动测试、观测入口和明确退化路径。

## 基线审计

### P0 连续性与数据安全

- 测试数据库曾与正式训练台账共用导出路径，存在 JSON 镜像污染风险；SQLite 正式数据未丢失。
- 弹幕队列只存在内存，服务重启会丢失尚未处理的真实消息。
- 多个直播页面可并发请求 `/api/next`，可能同时生成多条回复与语音。
- 情绪、认知、主动陪聊状态只在内存，重启后角色短期心理状态归零。
- 会话结束自动生成反思，但没有先经过候选审核，和新的“记忆需确认”原则不完全一致。

### P1 记忆质量

- 精确重复可去重，但语义重复、近似重复和相互冲突的记忆尚未形成维护报告。
- 记忆有创建时间与证据，但没有访问次数、最后调用时间和保留层级。
- 检索是可解释的混合词法方法，但缺少对错误召回、遗漏召回和跨用户污染的系统评测。
- 候选记忆已经支持人工确认，但缺少重复提示、冲突提示、批量归档和会话审阅状态。

### P1 大脑与行为

- 认知层只有单个目标、下一动作和低频反思，缺少开放任务生命周期、能力边界和行动结果反馈。
- 主动话题种类足够做演示，但缺少基于关系、最近经历、时间段和失败历史的选择评分。
- 情绪是多维状态，但刺激规则、恢复速度、关系调制和表达强度尚未形成校准数据集。
- LLM 能生成台词，却没有统一的角色一致性判分和回答后批评器。

### P2 运行与平台

- `server.js` 仍承担过多职责，运行设置、队列、API 和回复调度需要继续拆分。
- B站目前是事件适配层，正式长连接仍依赖开放平台凭据。
- osu! 视觉为规则识别 v1，缺少结算 OCR、谱面时轴对齐和失败点聚类。

## 四周交付

### 第 1 周：记忆工程

- 完成生产/测试数据隔离、候选审核、会话归档、语义重复与冲突报告。
- 增加记忆访问统计、保留层级、压缩建议和可逆合并。
- 建立记忆准确率、跨用户隔离、冲突替换和候选审批测试。

### 第 2 周：认知与情绪

- 建立观察、目标、计划、行动、结果、反思六阶段认知循环。
- 主动话题改为候选生成加评分，纳入时间、关系、近期经历、沉默次数和能力边界。
- 为情绪刺激、衰减、累积、关系调制和表达映射建立可重复校准测试。

### 第 3 周：训练与评测

- 建立离线场景集：身份、关系、记忆纠错、沉默、挑衅、能力不足、时间、音乐和 osu!。
- 模拟内容只进入隔离数据库，产生候选经验和失败报告，不污染真实角色经历。
- 输出人格一致性、记忆精确率、主动性、边界诚实度、重复率和延迟指标。

### 第 4 周：可靠性与运营

- 队列持久化、单消费者回复锁、失败重试、运行状态恢复和健康检查。
- 工作台增加会话审阅、记忆健康、评测历史和故障诊断。
- 完成压力测试、安全审计、备份恢复演练、操作手册和下一月差距报告。

## 不做的伪训练

- 不把模拟观众对话写成真实共同经历。
- 不让 LLM 自己批准自己的长期记忆。
- 不用大量 API 调用代替可重复的离线评测。
- 不把“更多 prompt”误认为更复杂的大脑。
