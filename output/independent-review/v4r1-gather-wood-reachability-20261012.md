## 第一次失败：可见木材包含高残干，较低候选的路径仍未确认

20:50:23.197 决策观察位置为 `(34.3,67,-6.5)`，模型看到四个最近的 exposed spruce_log：`(40,72,-4)`、`(42,69,-9)`、`(37,72,-14)`、`(37,73,-14)`，距离约8、8、9、10格。玩家 y=67，执行器拒绝高于玩家4格的木头（`y > 71`），所以列表中3根直接被标记 `target above safe height; towers forbidden`。这个门槛在保护不搭塔、不追高残干；不建议放松。

第4根 `(42,69,-9)` 高度只比玩家高2格，符合高度门槛，但 `directlyDig:false`，候选路径预检状态为 `partial`、21.0ms，结果为“reachability unconfirmed”，不是 `noPath`。执行器其余也试了 `(48,68,-2)`、`(53,71,-23)`、`(49,71,-27)`，均 `directDig:false`，预检各返回 `partial`。总计32个候选因超安全高度拒绝，4个候选因路径未确认拒绝；最终0块移除、库存无变化。用户提供的“下部树干先前已砍、当前剩上部残干”与观察到的高位木头相符，但本次日志未逐棵记录既往砍伐历史。

实现上，`exposed()` 只要求原木相邻六面中至少一面为空；它既不保证视线可达，也不保证有安全步行路径。模型观察扫描半径40、最多30块，再过滤 exposed 并只列4根；`gather_wood` 执行器扫描同一40半径、最多80候选。可见 `resources.wood` 因而是附近暴露方块清单，不是可采保证，也不是 executor 实际筛选全集。

路径预算是本次关键限制之一：`harvestRoute` 每候选最多24ms、整个 harvest 共80ms，最多12 probes；路径规划器以 `partial` 返回时，当前代码在 `finally` 里调用 `generator.return()` 并丢弃该搜索。四次预检各花21.0、16.3、16.1、16.4ms，总计69.9ms、4 probes，`budgetOverrun:false`。这说明探测没有超全局预算，却在每个候选的24ms小预算内未收敛；并非已经证明地形不可达。代码当前不会把某条 partial 搜索续跑到后续预算；如果要继续搜索，需要在仍遵守 `ctx.safe()` 和单动作上限的前提下延长/续跑单候选或有选择地分配预算，且应先用相同“低树干已砍、只剩高残干”的复现实例测延迟和安全性。

## 第二次失败：模型在空木材观察下再次请求采集

20:51:16.938 决策观察位于 `(-3.5,70,15.3)`，`resources.wood:[]`，且 `recentFailures` 已明确包含前一次“高于安全高度 / search budget timeout”的失败；模型仍选择 `gather_wood×4`。执行器在20:51:17.238–.284间快速失败，背包仍空；该 task 没有 `candidate_target` 或 `candidate_path_preflight` 事件，表示本次没有送入路径探测的 exposed 木头候选。这个错误在该调用中不是搜索预算耗尽，而是无 exposed candidate。此前模型选择 `explore south 24`，实际到达坐标为 `(-3.5,70,15.3)`，与模型所见空清单相符。

## 最小建议

1. 保留 `y > playerY + 4` 禁高残干规则和禁止搭塔规则。
2. 给木材观察加简短可行性提示：标明木头只是“暴露目标”，分别提示“高于安全高度”与“路径未验证”；不要把 exposed 列表呈现成可达保证。
3. 对第二次情况加明确的规划约束：当当前木材列表为空且近期同动作失败时，优先探索到新的木材候选区，避免立刻重复 gather。此例模型已得到空列表及前次失败，适合做针对性 planner/eval 样本。
4. 对第一种 `partial` 路径先做受控性能试验：保留总 CPU/总 probe 上限及安全检查，确认增加某个低位目标的有限搜索时间确实能完成安全终点后再考虑改预算；不要将 `partial` 改判为可达，也不要放宽高度门槛。

证据限度：日志证明模型观察列了哪些木头、执行器拒绝/预检了哪些目标，以及预检状态/耗时；它没有地形截图或三维场景快照，无法从日志单独证明 partial 目标最终可达或不可达。
