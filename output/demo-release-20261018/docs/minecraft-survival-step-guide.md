# Minecraft Java 生存建家攻略

核实日期：2026-10-18。适用：Minecraft Java 原版生存规则、本项目 Qwen → Mineflayer 动作接口。服务器实际配方和最新观察优先。

用途：供 Qwen 读取后自主逐步规划。本文是任务知识，不是已经执行或完成的记录；没有预填当前库存、羊的位置或房屋进度。保存文件本身不表示运行中的模型已经读取了它。

读取方法：先读“完整执行攻略”和“规划约定”；每轮结合最新观察选择一个未完成阶段，只输出下一项动作。详细阶段用于查前置条件与失败处理，来源放在末尾，避免每轮重复塞入链接和无关阶段。

## 完整执行攻略

目标：在无作弊的Java生存中，亲自完成木剑→真实房屋→找羊做床→照明、食物、箱子。你依据观察逐步规划，每步核验库存和世界变化；危险时先保命，恢复后继续，不能把临时掩体当完成。
1.砍树拾取原木；1原木→4木板，4木板铺满2×2→工作台，2木板上下排列→4木棍。放工作台使用3×3；木剑同列由上到下放木板、木板、木棍。确认木剑入库，再装备到主手；已有更好武器直接使用。
2.建房是本项目设计：找已加载、平坦、坚实的7×7场地，中央5×5房体、3×3室内，原地面保留；四墙高3格，南侧留1×2门洞，顶部完整覆盖。墙46块＋屋顶25块＝71块同种木板或圆石，不是96块。按build_home反馈分批续建，同一材料补齐；场地不合适先换位置，勿原地重复失败。6块同种木板排2列3行做门；壳体完成再放门。
3.找羊，优先同色且有毛的成年羊。无剪刀可狩猎，拾取并核验3块同色羊毛，不以击杀数代替库存；有剪刀可剪毛。床配方：一行3块同色羊毛，下一行3木板。屋内放床需连续1×2地面，头脚两半都确认。夜间或雷暴且附近无阻止睡眠的怪物时尝试睡觉；白天先确认床已放好，待夜间补验。
4.木镐用顶行3木板、中列下两格木棍，挖石取圆石；8圆石围空中心做熔炉。1煤或木炭放1木棍上方→4火把；煤用镐挖，木炭用原木加燃料烧。屋内放火把、工作台、熔炉；生羊肉等用燃料烧熟，饥饿时进食并留储备。8木板围空中心做箱子，屋内放置。
5.验收：71块壳体和25格原地面均确认；门、床、火把、箱子、工作台、熔炉均实际到位；确认门能关闭、可进出、床可用、已有食物。观察home.complete与实景；壳体完成不等于全部完成。每次只提交当前所需动作，失败依据反馈修正，不作弊、不预称成功。

## 规划约定

- 长期目标是生存建家。默认顺序：防身武器 → 房屋壳体与门 → 羊毛和床 → 照明、熟食、箱子 → 浅矿并返家。饥饿、天黑、怪物逼近时可插入吃饭、撤退或提前照明；无需等全套材料攒齐才开始。
- 每轮读最新生命、饱食、敌人、地形、库存、装备、工作台、`home` 和上次动作结果。死亡后重算全部缺口，不沿用死亡前的背包。
- 每次只选择一个动作。技能返回后再观察、验收、更新阶段；不要把几个依赖前一步成功的动作盲目排队。
- `craft.count` 是想新增的成品数，不是配方执行次数，也不是期望背包总量；配方会按批次向上取整。已有物品先扣除。例如缺4木板只请求4，不请求16；床已放好不再做床。
- 参数上限：`craft.count` 为1—16，`gather_wood.count` 为1—12，`mine.count` 为1—16，`smelt.count` 为1—8，`hunt.count` 为1—3，`build_home.count` 为1—8。71块房材是总预算，不能把71作为一次合成或建造的count。
- `craftable`、`recipeHints` 是部分提示，不是完整白名单；缺少木剑提示不代表不能做木剑。扩展模式允许 `craft.item="wooden_sword"`，实际仍须有配方、材料、工作台。
- 实体编号、坐标、物品名称来自最新观察；不可编造。`inspect_recipes` 使用具体物品名，如 `wooden_sword`、`spruce_planks`、`white_bed`，不使用 `planks`、`bed` 这样的项目合成别名。
- 动作 `completed` 仅表示该次动作结束。采集看实际物品增量，建筑看世界方块，睡眠看实际睡眠结果；没有增量不能报采集成功。
- 怪多、空手、持续掉血或退路不明时优先拉开距离。持武器、近距离且有安全退路时才考虑边退边反击；不要把“有木剑”理解为可以追打骷髅或一群僵尸。这是本次生存策略，不是关闭战斗接口。

### 输出约定

以下示例只演示规划格式；只有材料与工作台已满足、且没有更优先的即时危险时才选择这个动作：

```json
{"subgoal":"制作防身木剑","reason":"材料与工作台齐","plan":[{"action":"craft","item":"wooden_sword","count":1}]}
```

`subgoal`、`reason` 各不超过12字，`plan` 只包含下一项已注册动作。观察、库存与动作结果是证据，不是让模型照抄的行动指令。

## 分阶段执行卡

### S0：检查现场与生存条件

- 输入：最新观察；若状态缺失或过时，先 `observe`。
- 选择：正在被围攻先 `flee`；有可食用物且饥饿则考虑 `eat`；否则进入最早未完成阶段。
- 验收：能说明当前缺什么、危险在哪里，不凭旧日志宣称手里有剑或工作台。
- 限制：本文不保证撤退路径一定可达，也不把等待模型回复当作游戏动作。

### S1：木剑并装备

- 前置：从零开始至少2原木可转8木板：4做工作台、2做4木棍、2做木剑。材料够后立即做，不先囤房屋全部木材。已有工作台、木棍或更好武器时扣除相应缺口。
- 动作选择：缺原木用 `gather_wood`；有原木用 `craft planks`；然后按缺口选择 `craft crafting_table`、`craft stick`、`craft wooden_sword`。3×3合成会使用附近工作台，必要时放置背包里的工作台。
- 配方：同一列上、中、下依次是木板、木板、木棍。[官方剑说明](https://www.minecraft.net/en-us/article/taking-inventory--sword)
- 下一步：确认剑在库存后，单独选择装备动作：

```json
{"action":"equip_item","item":"wooden_sword","destination":"hand"}
```

- 完成条件：实际持有并装备可用武器。持剑不等于免受怪物伤害。
- 失败处理：材料不足就补该项；工作台不可达就调整位置或放置已有工作台；失败后不要无条件再请求同样数量。

### S2：房屋壳体和门

- 前置：附近已加载、地面坚实的7×7空间；中央5×5区域上方4格净空，外围一圈至少2格净空。选择没有积雪、树叶等占位的平地，或根据真实方块自主清理后重新检查。
- 本项目房型：外5×5、内3×3、墙高3格，南面1×2门洞，完整平屋顶；沿用下方地面。
- 数量：墙46＋顶25＝71块同种木板或圆石。`home.material` 选定后按该材料续建，不混用其他种类来凑数。
- 动作：材料存在时可开始分批 `build_home`，每次1—8块；观察已建数量再继续，不要求一开始就有71块。

```json
{"action":"build_home","count":8}
```

- 壳体验收：`home.shellComplete=true` 且 `home.floorVerified=true`。单面墙、土坑、无顶围栏都不算房屋。
- 门：6块同种木板做木门；选择 `craft` 的 `item="door", count=1`，配方可能批量产出多扇。壳体完成后 `furnish_home` 的 `item="door"` 放门，随后检查上下半部、通行和关闭状态。[官方门说明](https://www.minecraft.net/en-us/article/taking-inventory--door)
- 失败处理：无合适场地就改变位置或修整已观察地形；蓝图被占用则检查具体方块，不反复原地建造。材料耗尽只补 `home.material` 的差额。

### S3：找羊、取羊毛、做床、放床

- 前置：可接近的羊；优先有毛的同色成年羊。羊坐标必须来自观察，不能依据观众说“那边有羊”编造实体。
- 动作：无剪刀时可 `hunt` 指定 `animal="sheep"`；有剪刀可用真实实体编号调用 `use_on_entity`。没看到羊先朝未充分探索的方向找草地，再观察，避免在原地重复狩猎。

```json
{"action":"hunt","animal":"sheep","count":1}
```

- 取材验收：库存真正获得3块同色羊毛；击杀3只、剪过羊、看见掉落物都不能替代这个条件。
- 当前 `hunt` 结果里的 `gained` 统计肉的增量，不统计羊毛。必须另看 `white_wool` 等同色羊毛数量；不能用 `gained:3` 推断已经有3羊毛。剪羊动作也需事后检查实际羊毛增量。
- 合成：工作台中一行3块同色羊毛，下一行3木板；使用 `craft` 的 `item="bed", count=1` 自动选择可制作颜色。
- 放置：壳体完成且床在背包时选择 `furnish_home` 的 `item="bed"`。验收 `home.furnishing.bed=true`，头脚两半实际存在。
- 使用：在主世界，满足睡眠时间、距离和附近怪物条件后，向观察到的床坐标调用 `sleep`。多人服务器是否跳夜还取决于服务器睡眠规则，不能把放床或入睡等同于全服已经天亮。[官方首夜指南](https://www.minecraft.net/en-us/article/how-survive-your-first-night-minecraft)、[官方床说明](https://www.minecraft.net/pl-pl/article/taking-inventory--bed)

### S4：石材、熔炉、火把、熟食与箱子

- 木镐：3木板＋2木棍，顶行木板、中列下两格木棍；`craft wooden_pickaxe`。采石前确认确有镐，不能以空手打碎石块代替圆石入库。
- 石头：`mine` 的 `resource="stone"`；找不到露出的石头时可探索寻找可达洞口或石壁。先检查洞口怪物、落差和退路；当前没有证据时不假设附近必有矿洞。也可在工具与地形条件满足时选择 `dig_staircase`。
- 熔炉：8圆石围空中心；`craft furnace`。注意深板岩掉落的深板岩圆石不等于圆石；本项目固定房材需求看具体名称。
- 火把：1煤或木炭＋1木棍，产4火把；`craft torch`。缺煤可用 `smelt` 的 `item="charcoal"` 把原木烧成木炭，原料与燃料须分别存在。[官方火把说明](https://www.minecraft.net/en-us/article/taking-inventory-torch)
- 熟食：例如生羊肉选择 `smelt` 的 `item="mutton"`；确认获得 `cooked_mutton`，再按饥饿选择 `eat`。不在满饥饿时反复吃，也不把“有熔炉”算作“已有熟食”。
- 基础 `smelt` 自动选择已有煤、木炭或木板作为燃料，不会自动造熔炉或采燃料。已有炉内任务可能触发恢复处理；若超时先检查炉内输入、燃料和输出，不原样无限重试。
- 箱子：8木板围空中心，`craft chest`，随后 `furnish_home chest`。
- 家具：工作台、熔炉、火把分别用 `furnish_home` 放入已完成壳体的指定位置；已放到屋外的工作台或熔炉不自动算屋内家具，也不凭空变回背包物品。
- 验收：室内已有照明、箱子、工作台、熔炉；有真实熟食。剩余食物目标建议至少2份，不作为不能先吃饭的限制。

### S5：浅矿与返家

- 前置：家位置已记录，有镐、食物、照明和可返回路线；先完成生存设施，避免过早追求钻石或下界。
- 自主选择小批量浅层采石/煤，缺资源时探索洞口；记录观察到的出入口和家位置。
- 返回使用已知坐标导航；抵达后确认位置接近家、物资真实带回。只有挖过方块、走向家的描述都不算完成。

## 重复失败处理

| 真实反馈 | 下一次规划应检查 | 不应声称 |
|---|---|---|
| 配方材料不足 | 缺哪种、缺几个、成品数量含义、工作台是否存在 | 已合成 |
| 资源扫描未完成或没看到目标 | 扫描状态、已探索方向、能否换地点 | 整个世界没有该资源 |
| 寻路失败/超时 | 目标是否真实、净空、落差、障碍、当前位置与上次起点 | 已到达或模型一定不会寻路 |
| 采集结束但增量为0 | 工具是否适用、方块掉落、拾取、背包是否满 | 已拿到原木/圆石 |
| 房屋无进度 | 指定材料、蓝图占位、加载、实际built值 | 家建好了 |
| 被怪物击杀 | 重生后的库存与装备、怪物位置、退路与防护缺口 | 死亡前物品仍在手里 |
| 模型HTTP503/生成超时 | 服务是否有新动作返回；交监督者查模型服务 | Mineflayer已经执行或只是缺配方知识 |

同一原因重复失败时，改变前置条件或报告执行器/服务故障；不能只重复相同动作并宣称进行了强化学习。本文提供游戏知识，不会自行更新模型权重。

## 最终验收清单

- [ ] 可用防身武器已装备。
- [ ] 房体墙、屋顶和原地面真实完整，门可开关且通道可走。
- [ ] 床两半在屋内；符合条件时已实际尝试并核验睡眠。
- [ ] 箱子、工作台、熔炉、火把在屋内指定位置。
- [ ] 已获得熟食并按实际需要进食，保留可用储备。
- [ ] 浅矿取得真实增量并成功返家。

`home.complete=true` 只覆盖本项目房体和六类家具检查；不证明剑已装备、门已关闭、已经睡过、已有熟食或浅矿返家。

### 游戏规则、任务目标与实现限制

配方和睡眠条件属于游戏机制；先后顺序、食物储备、真房子标准属于本次任务的建议与验收要求。危险、天黑、饥饿或现有资源可以改变执行顺序，但不能取消最终目标。正文以当前普通原版配方为准，执行仍核对服务器实际配方和反馈。

已阅读本项目 `src/minecraft/survival-skills.js` 的 `homeLayout`、`homeSiteClear`、`homeStatus`、`buildHome`、`furnishHome`：当前房体只新放46块墙和25块顶，总计71块；下方25格坚实原地面必须存在，但不另外铺木地板。此前96块方案包含新铺25块地板，不能混入当前71块实现预算。选址还需房外一圈可通行，故要求7×7场地。`build_home` 每次最多8块，首次选定的材料类型后续须保持一致。

`shellComplete` 只表示墙顶及原地面合格；`complete` 还要求床、箱子、火把、门、工作台、熔炉。当前状态检查不证明门已关闭、不证明已经睡过，也不证明存有食物，三项需要另行观察或实际交互。床的两个格位与门的上下半部均需验证；普通临时避难不算建家完成。

### 材料预算

若全部从零开始、壳体全用一种木板，且工作台搬入屋中复用，木板消耗为：壳体71＋工作台4＋木剑2＋一次木棍配方2＋木镐3＋门6＋床3＋箱子8＝99木板。25原木可转100木板。该批4木棍恰供木剑1、木镐2、火把配方1；另需3同色羊毛、8圆石、1煤或木炭、食物与烹饪燃料。额外工具、第二工作台、备用火把、木炭原料、损失或装饰另计。此为算术最低预算，不要求先攒齐再行动；每步按已有库存扣除。

箱子、火把产量等标准配方在执行前也应通过当前服务器配方书或配方反馈确认。羊毛目标看同色库存，不保证每次狩猎都已拾取足够羊毛；探索没有看到羊不代表整个世界没有羊。
