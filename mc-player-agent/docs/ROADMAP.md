# 维护路线与阶段验收

这份路线用于控制范围，不代表已完成的能力或承诺日期。当前版本 `0.4.0-alpha.1` 的实际证据见 [VALIDATION](VALIDATION.md)。

## 已有基础

- 纯 Java 会话核心与 Minecraft 适配层分离，提供无游戏演示。
- 技能持有执行权、危险中断恢复、观测条件验收与独立任务记录。
- 会话时长、请求和动作硬预算；明确的超限停止与边界回归测试。
- 双加载器构建、核心自动化测试、原生拾取 GameTest 与源码打包。

## 0.4 第一阶段：开放技能与配置

当前交付以“外部开发者不修改核心代码即可注册并运行一个技能”为验收目标：

- 已实现：实例级注册、具名版本、旧技能别名、启动前封闭、可信 provider 服务发现。
- 已实现：沿用现有 JSON 配置，校验预算与技能选择、保留 F8 未展示字段、固定运行配置并记录哈希和技能版本。
- 已实现：独立 collect-return 示例与测试，从公开接口组合子任务，在模拟环境核对结果和停止路径。
- 尚未完成：第三方扩展的双加载器安装包、游戏端配置交互与真实模型任务验收。本阶段不代表通用插件平台、跨环境协议或安全沙箱已完成。

具体 API 和迁移规则见 [EXTENSIONS](EXTENSIONS.md)，已执行验证见 [VALIDATION](VALIDATION.md)。

## 下一阶段：建立真实游戏证据

优先完成 [EVALUATION](EVALUATION.md) 的客户端基础检查，再运行固定条件下的真实模型任务。保存失败运行；不只展示成功录像。

完成条件：两个加载器各有可复现的启动、配置、F8、F9、物理输入停止及记录写盘检查；公开结果注明版本、环境、模型、场景与样本数。上传 GitHub 后确认同一提交的 CI 通过。

## 再下一阶段：任务验收与无进展识别

依据真实运行记录选择问题，不先扩充玩法数量。

- 复合目标验收：支持组合条件，并区分模型提出的条件和用户实际目标；覆盖不完整条件、恶意降低条件和跨维度失效。
- 无进展检测：先定义各技能的有效进展信号，避免把合法等待或长距离移动误判成卡住。现有会话硬预算仅限制总消耗。
- 失败恢复：针对高频失败建立最小复现场景，修复后同时保留失败回归与新实测证据。

完成条件：每个规则有确定性测试，并在真实失败场景中复现修复；说明误报、漏报和适用范围。

## Beta 候选条件

这是未来的发布门槛，当前尚未达到：

1. 实机基础检查和选定任务评测完成，结果包含全部预先登记的尝试与失败原因。
2. 没有已知未解决的数据损坏、控制权无法收回或任务假成功等阻断问题。
3. 安装、升级、配置和来源说明与发行包一致，GitHub CI 对发布提交通过。
4. 有可复现演示和回归记录，明确仍不支持的场景；不以单元测试数量代替真实任务结果。

长期方向包含可持续的扩展生态；当前保持 Minecraft 优先，先完成一个外部扩展的开发、测试、安装与维护闭环。多玩家、远程服务、插件市场、热加载及不可信代码隔离尚未排入本轮实现。
