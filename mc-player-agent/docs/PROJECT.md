# MC Player Agent 项目定位

## 核心目标

维护方向：以 Minecraft 为第一个落地环境的开放、可扩展 agent harness，核心可脱离游戏运行和测试。使用者通过配置组装行为，开发者通过公开接口添加能力。`AgentHarness` 负责会话与调度，`PlayerControl` 提供 Minecraft 原生动作适配；接口及独立运行命令见 [HARNESS.md](HARNESS.md)。

让 AI 接管玩家当前的身体，在正常 Minecraft 生存规则下持续完成任务。用户可以随时取回控制权，并检查它做过什么、什么失败了、目标是否得到验收。

产品的中心是“目标 → 连续技能 → 服务器回执 → 验收与复盘”。F8 首先打开任务控制台。模型连接和提示词属于任务执行的配置。

## 项目边界

本项目独立维护构建、模组标识、Java 命名空间、配置、存档数据、界面和发行包。当前聚焦 Minecraft 1.21.1 的单人世界和本机局域网房主。

不引入伴侣召唤、角色皮肤、人物资源、语音演出、原项目插件协议或原项目服务作为核心架构。自然语言交互用于明确任务、说明计划和报告结果。

砍树、合成、寻路等基础玩法必然会与其他 Minecraft AI 项目存在交集。项目通过实际行为与结果形成区别：

| 设计方向 | 当前实现 | 仍需完善的验证 |
| --- | --- | --- |
| 有界运行 | 单调时间、模型请求、动作三类会话硬上限；状态切换不重置 | 阈值调优与语义无进展检测 |
| 任务持续性 | 技能持有执行权；后台规划不能直接抢夺技能；过期回复被拒绝 | 多地形长任务的完成率 |
| 可验收结果 | DONE 有本地条件检查；未确认状态单列；执行回执记录服务器刻 | 更完整的复合任务验收条件 |
| 可复盘运行 | 每次接管独立 UUID、JSONL 时间线和 JSON 汇总；异步写盘 | 历史任务浏览和汇总分析 |
| 存档隔离 | 世界、玩家、维度隔离记忆；运行记录位于实际存档目录 | 多存档往返的客户端长期测试 |
| 及时生存反应 | 本地危险检测、中断技能、危险解除后恢复 | 多种危险组合与恢复成功率 |
| 操作权清晰 | 接管真实玩家；F9 和物理输入归还控制 | 客户端连续人工接管测试 |

## 可自定义的范围

当前开放模型连接配置、提示词、执行预算、技能选择与可信 Java 技能注册，见 [EXTENSIONS](EXTENSIONS.md)。内置与外部技能通过同一注册协议提供。核心保留动作所有权、取消、预算执行与验收语义，不允许模型自行放宽这些约束。

Minecraft 动作与证据类型仍是当前协议；没有声称跨环境通用化。第二个真实环境出现后再检验并提炼抽象。模型 provider、记忆后端、任务条件组合属于后续设计，当前接口变化遵守 Alpha 迁移说明。

## 不同速度的工作

本地反应和动作跟随游戏刻运行。技能执行期间，大模型约每 5 秒进行一次后台检查；接口请求未结束时不会不断追加请求。不能为了“深度思考”而让身体等待固定 5 秒，也不能为了响应快而每次重新选择移动方向。

## 可验证的迭代顺序

1. 多个世界种子中完成采木、工具与基础庇护所任务。
2. 从完整运行记录统计完成率、无进展次数、危险中断次数、模型耗时与人工救援情况。
3. 根据失败回执补齐寻路、配方依赖、工具管理和脱困。
4. 在这些能力稳定后，再扩展协作、长任务调度与历史任务浏览。

详细阶段见 [ROADMAP](ROADMAP.md)，评测记录方法见 [EVALUATION](EVALUATION.md)。

这些是下一阶段的验收目标，不代表已通过长时间实机测试。当前测试结果应以每次发行的 verification.json 为准。

## 来源边界

`provenance.json` 区分原始下载中存在的来源文件与本机修改阶段新增的文件。源码位置不等于作者身份。实际继承的实现保留来源、修改记录和许可证。

新功能在本仓库独立实现和测试。不得通过删除署名、批量改类名或将同样界面换标题来宣称完全原创。原始下载快照的比较仅说明该快照，不能推断所有上游分支都不存在类似功能。
