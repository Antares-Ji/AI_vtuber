## 本轮工程规范化验证

- 开发者快速入口、核心演示、独立安装目录、双加载器构建与顺序 GameTest 均按文档运行。
- 检查器测试覆盖合法依赖、核心与客户端越层依赖、项目客户端类型、旧上游包、有效链接、缺失或未发布的目标、越界链接、绝对路径以及错误 URL。
- Gradle `help --task run` 确认核心任务支持 `--debug-jvm`，会暂停并监听端口 5005。没有实际连接 IDE 调试器，也未验证各 IDE 的导入界面。
- `.editorconfig` 约束后续编辑，现有 Java 业务源码未批量格式化。CI 使用与本地相同的仓库检查入口。

检查器只检查显式 import 和常见行内 Markdown 本地链接，不是完整依赖分析、外链检查或安全审计。

## 已有预算回归验证

9 项预算测试覆盖正数上限校验、等待规划时超时与记录落盘、迟到 DONE 回执、持续技能的动作上限、复盘请求上限、取消请求与维度切换、危险状态与时限、最后一次允许动作的正常完成，以及不同会话间的隔离。

默认上限为 20 分钟、120 次模型请求、2,000 个动作；它们是 Alpha 保护值，尚未通过真实玩法评测调优。源码、模型和游戏环境变化后，不能沿用本次结果推断后续版本。
