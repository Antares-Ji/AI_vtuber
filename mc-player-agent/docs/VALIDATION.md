## 新行为的证据

- 旧配置字段和省略版本号的读取、默认预算、分层覆盖、数组替换、类型与数值边界、未知字段拒绝、文件损坏及 I/O 失败。
- 保存后高级配置保留、profile 不可变与哈希可核对；任务记录不复制配置提示词和技能描述，配置记录不可中途改写。
- 注册表隔离、旧技能别名、重复／未知／禁用技能、启动前封闭、参数副本、工厂失败与空结果的显性错误。
- 外部技能实际通过公开 API 编译、发现和运行；立即完成的子任务仍须经库存和位置核验。子任务失败不启动后续任务，暂停、恢复和停止传播给当前子任务。
- 模拟示例显式传入的配置路径不存在时返回错误；不会悄悄使用默认配置运行。正常游戏的可选配置文件缺失仍按既有默认值启动。

## 未验证与限制

- 外部 Java 示例尚无 Fabric／NeoForge 扩展模组安装包；类路径 provider 发现接线已编译，两个真实客户端中的装载流程未验证。
- F8 保存与运行时 profile 的实际游戏交互、F9／物理输入连续接管、跨存档与长期生存未实测。
- 未调用真实模型，未验证真实任务完成率、模型服务当前兼容性或扩展在真实地形中的表现。
- GitHub 托管 CI、Windows 执行及 IDE 调试器连接未在本轮实际运行。工作流纳入新示例不等于云端 CI 已通过。
- 原生 GameTest 只有既有 3 类拾取场景，不能据此证明客户端技能或配置功能可靠。
- 插件与宿主同 JVM，技能选择不是安全权限边界。内置技能的参数校验尚未统一为严格 Schema；核心动作与观察仍使用 Minecraft 语义。
- 主任务仍使用单项验收条件；示例内部核对库存与位置，不等于通用复合验收已经实现。预算也不等于语义无进展检测或线程抢占。
