# 真实游戏评测规程

**状态：待执行。** 这份文件规定如何产生证据，不包含已完成的游戏实验，也不宣称成功率。

## 先做客户端基础检查

为 Fabric 与 NeoForge 各建一个 Minecraft 1.21.1 测试实例，使用待评测发行包，备份测试存档。逐项记录通过、失败或未执行：

| 检查 | 验收证据 |
| --- | --- |
| 首次安装与模型配置 | 能进入世界，F8 设置可保存；连接错误清楚显示且日志不包含密钥 |
| 执行与停止 | 分别用 F9、键盘与鼠标取回控制；停止后不继续发出动作 |
| 停止期间的迟到回复 | 请求尚未返回时停止，回复返回后不恢复接管 |
| 会话预算 | 通过测试宿主的小预算复现超限；游戏默认阈值另做人工检查，记录停止原因 |
| 运行记录 | `events.jsonl`、`summary.json` 属于本次 UUID，结束状态与实际操作一致 |
| 存档与维度隔离 | 两个测试存档和不同维度的记忆不串用；用副本验证旧目录迁移不覆盖新数据 |

发现无法收回控制、存档损坏或明确的假成功时停止批量评测，先保留证据并修复。

## 任务评测条件

先选一个加载器做试运行，跑通记录流程；试运行单独标注，不进入正式统计。正式批次开始前固定并记录：

- 项目版本、提交 SHA 或源码 ZIP SHA-256、JDK 与加载器版本。
- 模型服务、精确模型名、思考设置及服务日期；不要记录密钥。
- 世界种子、游戏规则、难度、出生点、起始背包、天气与时间。
- 原样目标文本、任务时限和人工干预规则。

至少选 3 个不同种子；每个种子每个任务做 3 次独立尝试，条件从相同存档副本恢复。每个加载器分别汇总；一个加载器的结果不能代替另一个。

建议从两个可直接核查的任务开始：

| 任务 | 起始条件 | 人工验收 |
| --- | --- | --- |
| 收集 8 个橡木原木 | 空背包，记录出生点和附近可用资源 | 原生背包中实际拥有至少 8 个橡木原木 |
| 制作 1 把木镐 | 固定数量橡木原木、空工作台状态，记录完整起始背包 | 原生背包中实际拥有至少 1 把木镐 |

不要预筛掉困难种子或删除失败尝试。复合的“采木→工具→庇护所”先作为探索任务；待复合验收实现后，再纳入正式完成率统计。

## 每次运行记录

记录项目版本、种子、任务、重复编号、运行 UUID、系统结束状态、人工验收、用时、人工干预次数、模型请求数、失败原因，以及脱敏记录或录像的位置。模型请求统计要区分已发送、已完成响应；当前运行汇总中的 `model_requests` 是已记录的响应数量。

用下面的表头建立本地 CSV，不预填示例成绩：

```csv
version,revision,loader,java_version,model,model_settings,seed,task,repeat,run_id,system_state,human_verified,elapsed_seconds,manual_interventions,completed_model_responses,failure_reason,evidence_path
```

`human_verified` 使用 true / false / unknown；未执行、日志丢失和实验条件不符均单列原因，不能静默删除。

## 统计与报告

- 无干预成功率 = 人工验收成功且人工干预为 0 的运行数 / 全部有效正式尝试数；同时给出分子和分母。
- 假成功 = 系统标为 `VERIFIED`，但人工验收失败。即使数量为 0，也只能说明这一批样本。
- 分别报告预算停止、模型错误、技能失败、人工接管与未知原因，不把 `UNVERIFIED` 合并为成功。
- 用时和请求数说明统计的是全部尝试还是仅成功尝试；不混用口径。
- 当前未实现 token 和费用核算，不能从请求数推算成本；没有服务端账单或 usage 数据时标注未测。

对外附环境、完整结果表、脱敏证据和已知限制。公开日志前移除密钥、服务凭证、个人路径与私人目标文本。
